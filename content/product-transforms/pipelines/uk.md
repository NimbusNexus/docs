# Конвеєри

Конвеєр — це JSON-документ, а ця сторінка описує його мову. Webhooks і Request Bins виконують ту саму мову на тому самому рушії, тож усе, про що ви дізнаєтеся тут, діє й там — у межах правил кожного продукту щодо заголовків. Щоб спробувати будь-що з цього без акаунта, скористайтеся [playground](/transforms/playground).

## Документ {#document}

Цей конвеєр залишає оплачені рахунки на суму від $1,000, вилучає email клієнта й будь-які номери телефону, додає два поля й заголовок і вказує, що до запиту додається bearer-токен:

```json
{
  "version": 1,
  "steps": [
    { "filter": { "type": "invoice.paid", "data": { "amount": { "$gte": 100000 } } }, "note": "Paid invoices of $1,000 or more" },
    { "drop": ["data.customer.email", "**.phone"] },
    { "set": { "event_type": "{{ type }}", "amount_display": "{{ data.amount | money(data.currency) }}" } },
    { "headers": { "set": { "X-Event-Type": "{{ type }}" } } },
    { "auth": { "type": "bearer", "secret": "sec_…" } }
  ]
}
```

`version` — це формат документа, завжди `1`, а не версія конвеєра. Кроки виконуються в тому порядку, у якому записані. Кожен — це обʼєкт з одним ключем кроку й, за бажання, `note` до 200 символів: консоль показує її на кроці, а коли запит відкинуто, її повертає відповідь. `filter` також може мати `action`.

Запуск бачить один запит: `body` — будь-яке значення JSON, `headers` і `meta`, доступне лише для читання. В API запуску усі три — це те, що ви надсилаєте. Кожен крок бачить тіло таким, яким його залишив попередній. В API й текстах помилок кроки нумеруються з 0, а в редакторі консолі — з 1.

| Крок | У консолі | Що робить |
|---|---|---|
| `filter` | **Filter** | Залишає запит, лише якщо він збігається, або, з `"action": "drop"`, відкидає його, якщо збігається. |
| `drop` | **Remove fields** | Вилучає поля з тіла. |
| `set` | **Set fields** | Додає або перезаписує поля. |
| `map` | **Reshape the body** | Замінює тіло тим, яке будуєте ви. |
| `headers` | **Headers** | Задає, вилучає або перейменовує заголовки. |
| `auth` | **Credential** | Вказує, що до запиту додається bearer-токен, Basic-автентифікація чи API-ключ, і називає слот, з якого вони беруться. |

### `filter` {#step-filter}

Залишає запит, лише якщо він збігається; інакше запуск відповідає `dropped`. З `"action": "drop"` усе навпаки: відкидається те, що збігається.

```json
{ "filter": { "data": { "status": "paid", "amount": { "$gte": 100000 } } }, "note": "Paid, $1,000 or more" }
```

- Кожен ключ — це умова, і виконуватися мають усі. Вкладений обʼєкт перевіряється за формою, як тут `data`.
- Просте значення збігається за рівністю JSON: `1` дорівнює `1.0`.
- Масив збігається, коли він дорівнює значенню або коли збігається один з його елементів: `{"data": {"tags": "urgent"}}` виконується для `["billing", "urgent"]`, а `{"data": {"items": {"sku": "A-1", "qty": 2}}}` потребує одного елемента, у якому є обидва.
- Поле, якого в запиті немає, збігається лише з `{"$exists": false}` і запереченнями, як-от `$neq`.
- Оператори: `$eq`, `$neq`, `$gt`, `$gte`, `$lt`, `$lte` (числа з числами, текст із текстом; мітки часу ISO порівнюються за часом), `$in`, `$nin`, `$exists`, `$startsWith`, `$endsWith`, `$contains` (текст або масив, що містить значення), а також `$and`, `$or` і `$not`, щоб поєднувати фільтри.
- `$headers`, `$meta` і `$body` перевіряють відповідну частину запиту: `{"$headers": {"x-github-event": "push"}}`.

### `drop` {#step-drop}

Вилучає поля з тіла: список від 1 до 50 шляхів. `*` відповідає будь-якому одному рівню, а `**` — будь-якій глибині, тож `**.email` вилучає кожне поле `email`, хоч би де воно було. Шлях, який нічому не відповідає, не є помилкою.

```json
{ "drop": ["data.customer.email", "data.cards[*].number", "**.phone"] }
```

### `set` {#step-set}

Додає або перезаписує поля: від 1 до 50 пар зі шляху й [значення](#values). Відсутні обʼєкти дорогою створюються, і кожне значення читає тіло таким, яким його застав крок. Шлях, що натрапляє на значення, яке не є обʼєктом, провалює запуск з `set_conflict`.

```json
{ "set": { "event_type": "{{ type }}", "data.total_cents": { "$ref": "data.amount" } } }
```

### `map` {#step-map}

Замінює тіло [значенням](#values), яке пишете ви, — зазвичай обʼєктом.

```json
{ "map": {
    "invoice_id": "{{ data.id }}",
    "amount": { "$ref": "data.amount" },
    "amount_display": "{{ data.amount | money(data.currency) }}",
    "event": "{{ type }}"
} }
```

Для запиту `invoice.paid`, у якого `data` — це `{"id": "in_42", "amount": 150000, "currency": "usd"}`, тіло стає таким:

```json
{ "invoice_id": "in_42", "amount": 150000, "amount_display": "1,500.00 USD", "event": "invoice.paid" }
```

### `headers` {#step-headers}

Задає заголовки через `set`, вилучає їх через `remove` і перейменовує через `rename` — у порядку remove, rename, set. Назви збігаються незалежно від регістру, а задана назва замінює всі її написання.

```json
{ "headers": { "set": { "X-Event-Type": "{{ type }}", "Content-Type": "application/json" } } }
```

Крок `headers` не може задати заголовок, що належить зʼєднанню, як-от `Host` чи `Content-Length`, а також `Set-Cookie`. Не може він задати й `Authorization`, `Cookie` чи `X-Api-Key`, бо значення лежало б у документі, який повертає кожне читання: облікові дані додаються кроком `auth`. Продукт, який виконує конвеєр за посиланням, також застосовує до нього власні правила щодо заголовків.

### `auth` {#step-auth}

Вказує, що до запиту додаються облікові дані, і називає слот, з якого вони беруться:

| `type` | Що додає |
|---|---|
| `bearer` | `Authorization: Bearer` і облікові дані. |
| `basic` | `Authorization: Basic` з `username` і облікових даних як пароля. |
| `api_key`, `"in": "header"` | Облікові дані в заголовку з назвою `name`, після необовʼязкового `prefix`, як-от `"Token "`. |
| `api_key`, `"in": "query"` | Облікові дані як параметр запиту `name` в URL отримувача. |

```json
{ "auth": { "type": "api_key", "in": "header", "name": "X-Api-Key", "secret": "sec_…" } }
```

`secret` — це ідентифікатор [слота](/docs/product-transforms/reference#slots), який є в робочому просторі. Це ніколи не значення: вставлене туди значення відхиляється з `invalid_secret`, і відмова його не повторює. Продукт, який виконує конвеєр за посиланням, зіставляє слот із власним секретом ([Облікові дані](/docs/product-transforms#credentials)). Тестування й API запуску показують заголовок чи параметр із замаскованим значенням.

Кроки `auth` стоять після всіх інших кроків, тож жоден крок не може прочитати, скопіювати чи перевірити облікові дані.

## Шляхи та значення {#values}

Шлях указує на поле тіла:

| Шлях | Указує на |
|---|---|
| `data.customer.email` | Поле. |
| `data.items[0].sku` | Елемент списку. |
| `data['first name']` | Ключ, у якому є пробіл, крапка чи дужка. |
| `data.items[*].sku` | Кожен елемент; у значенні — їхній список. |
| `**.email` | `email` на будь-якій глибині; лише в `drop`. |
| `$meta.source`, `$headers.x-name`, `$body.data` | Метадані запиту, один із його заголовків або його тіло; лише в значенні. |

`set` приймає прості шляхи, `drop` — `*` і `**`, а значення читає з `*`, але не з `**`.

Значення в `set`, `map` чи заголовку — це JSON, який копіюється так, як записаний, за двома винятками:

- **`{{ path }}`** у рядку вставляє значення як текст. Відсутнє значення чи `null` нічого не вставляє, а обʼєкт або список вставляється як JSON. `{{ 'text' }}` і `{{ 42 }}` — літерали, тож буквальне `{{` записується як `{{ '{{' }}`.
- **`{"$ref": "path"}`** вставляє саме значення й зберігає його тип: число лишається числом, список — списком. Додайте `"default"` на випадок, коли шляху немає.

Вираз може пропустити своє значення через фільтри, зліва направо: `{{ data.amount | money(data.currency) }}` дає `1,500.00 USD` для суми 150000 у `usd`.

| Фільтр | Дає |
|---|---|
| `upper`, `lower` | Текст великими чи малими літерами. |
| `default(x)` | `x`, коли значення немає, воно `null` або порожнє. |
| `truncate(n)` | Щонайбільше `n` символів, а далі `…`. |
| `join(sep)` | Список як текст, зʼєднаний через `", "`, якщо не вказати `sep`. |
| `length` | Кількість елементів, ключів чи символів. |
| `json`, `json(indent)` | Значення як компактний JSON або з відступом від 1 до 8 пробілів. |
| `number(digits)` | Число з такою кількістю знаків після коми. |
| `money(currency)` | Суму в мінімальних одиницях валюти, відформатовану; валюти без дробової частини й із трьома знаками теж. |
| `date(format)` | Час у форматі ISO 8601 або в секундах epoch, в UTC, з `%Y`, `%m`, `%d`, `%H`, `%M`, `%S` тощо. |
| `escape(target)` | Текст, який не може форматувати повідомлення в чаті: `slack` (за замовчуванням), `discord` або `markdown`. |
| `code(target, max, language)` | Текст як блок коду в розмітці `slack`, `discord` чи `markdown`, який текст не може завершити передчасно, обрізаний до `max` символів. |

Циклів, умов і обчислень немає: умова — це крок `filter`, а список стає текстом через `[*]` і `join`.

## Шаблони {#templates}

У галереї є готові конвеєри, з яких можна почати. У консолі вони під **Start from a template**. Через API `GET /v1/pipelines/templates` повертає кожен шаблон із його `pipeline`. Після збереження шаблону ви отримуєте власний конвеєр: змінюйте його, як будь-який інший; із шаблоном він більше нічим не повʼязаний.

| `id` | Шаблон | Що надсилає |
|---|---|---|
| `slack` | **Slack message** | Для вхідного вебхука Slack: тип події як заголовок повідомлення, її ідентифікатор і час, а дані — блоком коду. |
| `discord` | **Discord message** | Для вебхука каналу Discord: embed із типом події, її даними блоком коду, ідентифікатором і часом. Нікого не згадує. |
| `teams` | **Microsoft Teams card** | Для вебхука робочого процесу Teams: Adaptive Card із типом події, її ідентифікатором і часом, а дані — моноширинним шрифтом. |
| `keep_fields` | **Keep only these fields** | `id`, `type`, `created_at` і `version` події та лише ті поля `data`, які перелічує його `map`, починаючи з `data.id`. Перелічене поле, якого в події немає, надсилається як `null`. |
| `drop_personal` | **Drop personal data** | Подію без `email`, `phone`, `first_name`, `last_name`, `address`, `billing_address`, `shipping_address`, `date_of_birth` і `ip_address` на будь-якій глибині. Звичайне `name` лишається, бо воно часто називає план чи продукт. |

Кожен шаблон для чату — це крок `map` і крок `headers`, що задає `Content-Type: application/json`, і працює він з будь-якою подією. Відсутній тип показується як «Event», а відсутній ідентифікатор чи час — як «—», дані обрізаються під обмеження застосунку, і ніщо в події не може відформатувати повідомлення, когось згадати чи передчасно завершити блок коду.

## Ліміти {#limits}

Конвеєр не має циклів, годинника й мережі, а фіксовані межі обмежують кожен запуск. Якщо межу перевищено, запуск відповідає `failed` із причиною, а документ, що її перевищує, відхиляється під час збереження.

| Що | Ліміт | Відхиляється як |
|---|---|---|
| Документ як компактний JSON | 64 KiB | `too_large` |
| Кроки | 20 | `too_many_steps` |
| Шляхи в `drop`, поля в `set`, назви в кожній частині кроку `headers` | 50 | `invalid_value` |
| Налаштування кроку як компактний JSON | 16 KiB | `too_large` |
| Примітка кроку | 200 символів | `invalid_value` |
| Вкладеність у кроці й у тілі | 32 рівні | `too_deep`, `input_too_deep` |
| Тіло, яке читає крок | 256 KiB | `input_too_large` |
| Тіло, яким відповідає запуск | 256 KiB | `output_too_large` |
| Одне значення, яке формує крок | 64 KiB | `value_too_large` |
| Робота за один запуск | 100,000 прочитаних чи скопійованих значень; текст — одне на 128 символів | `too_many_nodes` |
| Заголовки наприкінці запуску | 50 | `too_many_headers` |
| Значення одного заголовка | 8 KiB | `header_too_large` |

У playground менші межі: документ на 16 KiB, тіло на 32 KiB і 10,000 прочитаних чи скопійованих значень за один запуск.
