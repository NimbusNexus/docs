# Плаваючі IP

Плаваючий IP — це публічна IP-адреса, яка **належить вашому проєкту, а не конкретній VM**. Ви виділяєте адресу, підʼєднуєте її до VM, і вона стає публічним IP цієї VM. Згодом відʼєднайте її й підʼєднайте до іншої VM — тепер ваш трафік іде на нову VM, а адреса не змінюється.

## Навіщо потрібні плаваючі IP {#why}

IP, який VM отримує за замовчуванням, **ефемерний**: коли VM видаляють, IP повертається до пулу, а створена заново VM отримує новий. Для воркерів без стану за балансувальником навантаження це нормально. А от для такого це жахливо:

- Усе, до чого звертаються через DNS-запис A/AAAA (запис ламається щоразу, коли VM створюють заново)
- Усе, що є в списку дозволених IP партнера (партнерові доводиться знову додавати адресу до списку дозволених)
- Blue/green-розгортання, коли трафік треба перекинути між двома прогрітими VM без поширення DNS

Плаваючий IP розвʼязує всі три проблеми. IP живе довше за будь-яку конкретну VM; ви перекидаєте його з однієї VM на іншу за ~2 секунди одним викликом API.

## Привʼязка до регіону {#region}

Плаваючі IP працюють **у межах регіону**. IP, виділений у `us-east-1`, можна підʼєднати лише до VM у `us-east-1`. Для міжрегіонального failover потрібне одне з двох:

- Плаваючий IP у кожному регіоні + failover на рівні DNS (за затримкою, з перевірками стану)
- Продукт з anycast-IP, якого ми зараз не пропонуємо

Це обмеження ми не плануємо прибирати: міжрегіональні плаваючі IP вимагали б глобальної маршрутизації публічних BGP-анонсів, а це зовсім інший продукт, ніж виділення адрес у кожному регіоні.

## Тарифікація {#billing}

- **Підʼєднаний** до запущеної VM: **\$0** — IP входить у вартість VM.
- **Підʼєднаний** до зупиненої VM: \$2,50/міс — так само, як позиція зарезервованого IP для VM.
- **Не підʼєднаний**: \$2,50/міс — той самий тариф. Ми беремо плату за непідʼєднані IP, щоб їх не накопичували про запас: так регіональний пул вичерпувався б швидше, ніж ми можемо його розширювати.

Стандартний підхід: виділяйте IP, коли він потрібен, одразу підʼєднуйте, а коли закінчите — звільняйте.

## IPv4 чи IPv6 {#ipv4-ipv6}

Плаваючі IP бувають обох видів. `version: 'ipv4'` — варіант за замовчуванням (і те, що потрібно більшості). `version: 'ipv6'` виділяється з нашого блоку `/48` у кожному регіоні; обидва варіанти публічні й маршрутизовані.

До VM можна одночасно підʼєднати один плаваючий IPv4 і один плаваючий IPv6. Кілька IPv4 на одну VM не підтримується; якщо на одній VM потрібно кілька адрес, використовуйте приватні адреси VPC з NAT.

## Семантика підʼєднання / відʼєднання {#attach}

- **Підʼєднання** атомарне: VM отримує адресу протягом ~2 секунд. Наявні TCP-зʼєднання з попереднім публічним IP VM (якщо він був) обриваються — просто змінюється таблиця маршрутизації ядра.
- **Відʼєднання** не звільняє IP, а лише відвʼязує його від VM. IP тарифікується, доки ви не викличете DELETE.
- Повторне підʼєднання того самого IP до іншої VM — це і є шлях failover. Відʼєднайте, підʼєднайте до нової цілі, DNS не змінюється.
