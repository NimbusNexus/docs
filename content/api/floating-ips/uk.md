# Плаваючі IP

Плаваючий IP — це публічна IP-адреса, яка **належить вашому проєкту, а не конкретній VM**. Ви резервуєте адресу в зовнішній мережі, призначаєте її порту VM, і вона стає публічним IP цієї VM. Згодом відʼєднайте її й підʼєднайте до іншої VM — тепер ваш трафік іде на нову VM, а адреса не змінюється.

## Навіщо потрібні плаваючі IP {#why}

IP, який VM отримує за замовчуванням, **ефемерний**: коли VM видаляють, IP повертається до пулу, а створена заново VM отримує новий. Для воркерів без стану за балансувальником навантаження це нормально. А от для такого це жахливо:

- Усе, до чого звертаються через DNS-запис A/AAAA (запис ламається щоразу, коли VM створюють заново)
- Усе, що є в списку дозволених IP партнера (партнерові доводиться знову додавати адресу до списку дозволених)
- Blue/green-розгортання, коли трафік треба перекинути між двома прогрітими VM без поширення DNS

Плаваючий IP розвʼязує всі три проблеми. IP живе довше за будь-яку конкретну VM; ви перекидаєте його з однієї VM на іншу одним викликом API.

## Привʼязка до регіону {#region}

Плаваючі IP працюють **у межах регіону**. IP береться із зовнішньої мережі одного регіону й підʼєднується лише до портів у цьому регіоні.

## Тарифікація {#billing}

Плаваючий IP тарифікується за власною ціною від моменту створення до видалення — незалежно від того, підʼєднаний він чи ні. Підʼєднання до VM не включає його у вартість VM. Актуальну ціну наведено на сторінці [Дані про ціни](/docs/api/pricing-data).

Стандартний підхід: створюйте IP, коли він потрібен, одразу підʼєднуйте, а коли закінчите — видаляйте.

## IPv4 чи IPv6 {#ipv4-ipv6}

Поля версії немає: адреса береться із зовнішньої мережі, яку ви вказуєте в `floating_network_id`, а `POST /api/v1/floating_ip/reserve` може також прийняти конкретну `ip_address`. `GET /api/v1/floating_ip/artifacts` перелічує зовнішні мережі з `ip_version` кожної підмережі.

Кожен плаваючий IP привʼязується до одного фіксованого IP на одному порту (`vm_port_id` і `vm_ip_address`), тож VM з кількома фіксованими IP може мати по одному плаваючому IP на кожному.

## Семантика підʼєднання / відʼєднання {#attach}

- **Підʼєднання** — це `POST /api/v1/floating_ip/allocate` із зовнішньою мережею (`floating_network_id`), портом (`vm_port_id`) і його фіксованим IP (`vm_ip_address`). Передайте `floating_ip_id`, щоб підʼєднати адресу, яка у вас уже є; без нього allocate створює нову. `GET /api/v1/floating_ip/artifacts?resource_id=<id>` перелічує порти VM або балансувальника навантаження.
- **Відʼєднання** — це `POST /api/v1/floating_ip/deallocate`. Воно не звільняє IP, а лише відвʼязує його від VM. IP тарифікується, доки ви його не видалите — через `DELETE /api/v1/floating_ip/` (його ID в `ids`) або `deallocate` з `delete: true`.
- Повторне підʼєднання того самого IP до іншої VM — це і є шлях failover. Відʼєднайте, підʼєднайте до нової цілі, DNS не змінюється.
