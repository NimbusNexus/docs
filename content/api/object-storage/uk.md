# Обʼєктне сховище

Обʼєктне сховище NimbusNexus надає **API AWS S3**. Наявні інструменти й бібліотеки — CLI `aws s3`, boto3, офіційні SDK для Java/Go/Node, будь-який фреймворк, що працює з S3, — працюють без змін, щойно ви націлите їх на наш ендпоінт і підставите наші облікові дані.

## Що сумісне з S3, а що ні {#compat}

Ми реалізуємо операції, якими користуються 90 % клієнтів S3:

- CRUD для bucket-ів (`PutBucket`, `GetBucket`, `DeleteBucket`)
- CRUD для обʼєктів (`PutObject`, `GetObject`, `DeleteObject`, `HeadObject`, `ListObjects`/`ListObjectsV2`)
- Багаточастинне завантаження (`CreateMultipartUpload`, `UploadPart`, `CompleteMultipartUpload`)
- Попередньо підписані URL (sig v4)
- Метадані обʼєктів, content-type, користувацькі заголовки
- Шифрування на боці сервера (завжди ввімкнене, AES-256)

Ми **не** реалізуємо:

- Специфічний для AWS IAM (у нас власний — для API керування використовуйте модель bearer-токенів, описану на сторінці [Автентифікація](/docs/authentication); облікові дані S3 видаються окремо).
- S3 Object Lock / відповідність вимогам WORM (заплановано на IV квартал 2026 року).
- S3 Select (запити на боці сервера).
- Міжрегіональну реплікацію через API S3 (натомість ми надаємо її через API керування, із прозорішими цінами).

Якщо ваш застосунок використовує функцію S3, якої немає в списку підтримуваних, він отримає `501 Not Implemented` з назвою операції в `error.code`. Перейдіть на підтримуваний еквівалент або створіть запит на функцію.

## Класи сховища {#classes}

Три класи, які вибирають під час запису обʼєкта (або задають за замовчуванням для bucket-а):

| Клас | За GB·міс | Затримка першого байта | Мінімальний строк зберігання | Коли використовувати |
| --- | --- | --- | --- | --- |
| `standard` | \$0,013 | <50 мс | Немає | Гарячі дані — вебресурси, часте читання, усе, що віддається наживо. |
| `ia` | \$0,007 | <50 мс | 30 днів | «Infrequent access» — дані потрібні час від часу, але тоді потрібні швидко. Та сама швидкість отримання, що й у Standard, удвічі нижчий тариф на зберігання, плата за отримання за кожен GB. |
| `cold` | \$0,004 | 1–60 хв | 90 днів | Архів — бекапи, сирі логи, зберігання для відповідності вимогам. Зберігати дешевше, отримувати повільніше. |

Мінімальний строк зберігання означає: якщо ви видалите обʼєкт до завершення мінімального вікна, то заплатите тариф за GB за решту вікна. У цьому й полягає «infrequent» в IA: дешево, якщо обʼєкти просто лежать, і дорого, якщо ви їх часто замінюєте.

Для суто архівних потреб, коли ви майже ніколи не читаєте дані, див. [Холодне сховище]({{BASE_URL}}/cold-storage) — окремий архівний продукт із ще дешевшими тарифами (фіксовано \$0,004/GB·міс плюс плата за отримання).

## Egress — те, що справді відрізняється {#egress}

Найбільша відмінність від AWS S3 — **як тарифікується egress**:

- VM ↔ обʼєктне сховище **в одному регіоні**: **безкоштовно**, завжди. Це основний шлях даних для більшості навантажень (ваші VM звертаються до ваших bucket-ів), і ми за нього не беремо плати. Фактичний egress для продакшн-трафіку, який не виходить за межі одного регіону: \$0.
- Egress у публічний інтернет: \$0,009/GB, причому перший **1 TB на місяць безкоштовний** для кожного проєкту. Для порівняння: AWS S3 бере \$0,09/GB за перші 10 TB.
- Міжрегіональний egress: \$0,005/GB. Дешевше за egress у публічний інтернет, бо трафік іде нашою магістральною мережею, а не відкритим інтернетом.

Рядок «безкоштовна передача даних до VM у межах регіону» на маркетинговій сторінці — це справжнє архітектурне зобовʼязання, а не акція. Мета — зробити економічно вигідними багаторівневі архітектури (обʼєктне сховище як джерело істини, а перед ним VM, які читають і віддають дані).

## Імена bucket-ів {#naming}

Імена bucket-ів **глобально унікальні серед усіх тенантів NimbusNexus** — те саме правило, що й в AWS. Вони сумісні з DNS: малі літери, 3–63 символи, без підкреслень, без дефісів на початку/в кінці. Захоплення імен bucket-ів — головна причина займати важливі імена завчасно.

Імена bucket-ів зʼявляються в URL: `https://<bucket>.{{S3_HOST_US_EAST_1}}/<key>` або в стилі шляху: `{{S3_ENDPOINT_US_EAST_1}}/<bucket>/<key>`. Працюють обидва стилі; клієнти SDK вибирають один залежно від своєї конфігурації.

## Списки, пагінація, продуктивність {#listing}

`ListObjectsV2` повертає до 1 000 ключів на запит, відсортованих за ключем у лексикографічному порядку. Якщо ключів більше ніж 1 000, гортайте сторінки за допомогою `continuation_token` — так само, як в S3.

Для дуже широких bucket-ів (мільйони ключів) використовуйте **список із роздільником**: передайте `delimiter=/`, щоб отримати список у стилі каталогів, де ключі згруповано за префіксом. Отримання списку «каталогу» з роздільником сканує лише його безпосередніх нащадків, а не весь bucket.

Обʼєкти класу Cold у відповіді зі списком повертаються так само, як Standard / IA: отримання списку не запускає отримання даних, це робить лише `GetObject`. Bucket класу Cold зі 100 млн обʼєктів можна просканувати безкоштовно; відновлення обʼєкта з Cold має власну плату за GB.

## Що далі {#next-steps}

- [Автентифікація](/docs/authentication) — автентифікація bearer-токеном для API керування. Облікові дані S3 (ключ доступу + секретний ключ) видаються окремо через API керування.
- [Блокове сховище](/docs/api/block-storage) — коли вам потрібна файлова система, а не сховище «ключ — значення», або потрібна семантика POSIX.
- [Редактор Mosaic]({{BASE_URL}}/products/mosaic) — браузерний редактор файлів YAML/JSON/Markdown у ваших bucket-ах. Безкоштовний для кожного акаунта, що користується Сховищем.
