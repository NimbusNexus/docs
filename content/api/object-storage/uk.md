# Обʼєктне сховище

Обʼєктне сховище NimbusNexus зберігає файли як обʼєкти в контейнерах, що належать вашому проєкту. Контейнерами й обʼєктами ви керуєте через `/api/v1/object_storage/` з тими самими обліковими даними, що й у решті API.

## Контейнери {#containers}

`POST /api/v1/object_storage/` створює контейнер. Задайте `public_read: true`, щоб будь-хто міг читати окремі обʼєкти, URL яких знає, і додайте `public_listing: true`, щоб будь-хто міг ще й переглядати список вмісту контейнера; на `public_listing` без `public_read` API відповідає `400`. На назву, яка вже існує, API відповідає `409`.

`GET /api/v1/object_storage/` перелічує ваші контейнери з їхніми `bytes` і `count`. `PATCH /api/v1/object_storage/{container_name}` оновлює метадані контейнера, а `DELETE /api/v1/object_storage/{container_name}` видаляє порожній контейнер; якщо в контейнері ще є обʼєкти, API відповідає `409`.

## Назви контейнерів {#naming}

Назва контейнера — це 3–63 символи: малі літери, цифри й дефіси, причому починатися й закінчуватися вона має літерою або цифрою. Підкреслення, крапки й пробіли не дозволені, як і назва у форматі IP-адреси.

## Обʼєкти {#objects}

- `POST /api/v1/object_storage/{container_name}/objects` завантажує новий обʼєкт як multipart-поле `file`; обʼєкт отримує назву з `object_name`, а без нього — назву файлу. На назву, яка вже існує, API відповідає `409`.
- `PUT /api/v1/object_storage/{container_name}/objects/{object_name}/content` замінює вміст обʼєкта.
- `GET /api/v1/object_storage/{container_name}/objects/{object_name}/content` повертає його вміст: текст — у UTF-8, двійковий вміст — у кодуванні base64.
- `GET` і `PATCH /api/v1/object_storage/{container_name}/objects/{object_name}` читають і оновлюють його метадані, а `DELETE` за тим самим шляхом його видаляє.
- `POST /api/v1/object_storage/{container_name}/objects/{object_name}/copy` і `/move` копіюють або переміщують його під нову назву чи в інший контейнер.

Назва обʼєкта може містити `/`, що читається як шлях до папки.

## Списки й пагінація {#listing}

`GET /api/v1/object_storage/{container_name}/objects` перелічує обʼєкти контейнера. Гортайте сторінки за допомогою `limit` і `marker` (остання назва, яку ви бачили) або задайте `full_listing=true`, щоб отримати всі обʼєкти в одній відповіді. `prefix` залишає лише назви, що з нього починаються.

Передайте `delimiter=/`, щоб отримати список у стилі папок: обʼєкти цього рівня повертаються в `objects`, а префікси на рівень нижче — у `subdirs`.

## Короткочасні облікові дані {#credentials}

`POST /api/v1/object_storage/credentials` випускає короткочасні облікові дані, привʼязані до проєкту, до якого привʼязана ваша сесія, і повертає їхні `trust_id` та `expires_at`. Бажаний строк дії можна вказати в `ttl_seconds`; сервер обмежує його зверху. Окремий редактор надсилає `trust_id` у заголовку `X-Trust-Id` у наступних викликах обʼєктного сховища й так дістається до сховища проєкту, не маючи ні вашого повного токена, ні будь-якого довготривалого секрету; кожен виклик при цьому, як завжди, проходить автентифікацію. `DELETE /api/v1/object_storage/credentials/{trust_id}` відкликає їх.
