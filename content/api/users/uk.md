# Користувачі

Користувач — це ідентичність усередині [робочого простору](/docs/api/workspaces). Користувачі мають ролі в [проєктах](/docs/api/projects) робочого простору (які надають дозволи), можуть генерувати API-ключі (кожен належить користувачу й привʼязаний до одного проєкту) і можуть використовувати довіри, щоб діяти від імені інших проєктів.

## Користувач ≠ обліковий запис для входу {#identity-model}

«Користувач» у цьому API — це **запис ідентичності**, а не людина. Кожен користувач належить рівно до одного робочого простору, і його імʼя там унікальне. У межах робочого простору той самий користувач може мати різні ролі в різних проєктах:

- Одну роль у `prod` (продакшн-проєкт)
- Іншу роль у `staging`
- Жодної ролі в `dev`

Що користувач може робити в проєкті, визначають ролі, які він там має, надані безпосередньо або через [групу](/docs/api/user-groups). Саме на цю межу варто спиратися, щоб обмежити радіус ураження: надавайте ролі в `prod` лише тим користувачам, яким вони потрібні.

## Що можна робити з користувачем {#actions}

- **Створити** — додати користувача в робочий простір того, хто здійснює виклик, з `name` і, за бажанням, `password`, `description` та прапорцем `enabled`.
- **Отримати** — прочитати запис користувача за ID.
- **Оновити** — змінити імʼя, опис, прапорець увімкнення або пароль.
- **Видалити** — видалити назавжди. Усі призначення ролей і API-ключі користувача атомарно відкликаються.

Усі чотири дії потребують ролі `admin`. Оновлення й видалення приймають також API-ключ адміністратора. Створення й отримання потребують сесії, привʼязаної до самого робочого простору, а не до одного з його проєктів. API-ключ завжди привʼязаний до одного проєкту, тож на виклик із ключем обидві дії відповідають `400`.

Пароль можна передати, але API ніколи його не повертає: запис користувача містить лише `id`, `name`, `description` і `enabled`.

Окремої дії «вимкнути», відмінної від «видалити», немає. Якщо потрібне мʼяке вимкнення (зберегти історію аудиту, заборонити вхід), встановіть `enabled: false` через оновлення — це і є шлях мʼякого вимкнення. Видалення — це остаточне видалення + відкликання всього.

## Чого робити не можна {#cant-do}

- **Переносити користувача в інший робочий простір.** Створіть нового користувача в цільовому робочому просторі, надайте йому там потрібні ролі й видаліть старого. У межах одного робочого простору переносити нічого: надайте користувачу роль в іншому проєкті.
- **Отримувати користувача з іншого робочого простору.** Отримання знаходить лише користувачів робочого простору того, хто здійснює виклик. Для будь-кого іншого API відповідає `404`.
