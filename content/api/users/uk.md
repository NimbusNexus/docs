# Користувачі

Користувач — це ідентичність усередині [робочого простору](/docs/api/workspaces). Користувачі мають ролі в [проєктах](/docs/api/projects) робочого простору (які надають дозволи) і можуть генерувати API-ключі (кожен належить користувачу й привʼязаний до одного проєкту).

## Користувач ≠ обліковий запис для входу {#identity-model}

«Користувач» у цьому API — це **запис ідентичності**, а не людина. Кожен користувач належить рівно до одного робочого простору, і його імʼя там унікальне. У межах робочого простору той самий користувач може мати різні ролі в різних проєктах:

- Одну роль у `prod` (продакшн-проєкт)
- Іншу роль у `staging`
- Жодної ролі в `dev`

Що користувач може робити в проєкті, визначають ролі, які він там має, надані безпосередньо або через [групу](/docs/api/user-groups). Саме на цю межу варто спиратися, щоб обмежити радіус ураження: надавайте ролі в `prod` лише тим користувачам, яким вони потрібні.

## Що можна робити з користувачем {#actions}

- **Отримати** — прочитати запис користувача за ID.
- **Оновити** — змінити імʼя, опис, прапорець увімкнення або пароль.
- **Видалити** — видалити назавжди. Усі призначення ролей і API-ключі користувача атомарно відкликаються.

Усі три дії потребують ролі `admin`. Оновлення й видалення приймають також API-ключ адміністратора. Отримання потребує сесії, привʼязаної до самого робочого простору, а не до одного з його проєктів. API-ключ завжди привʼязаний до одного проєкту, тож на отримання з ключем API відповідає `400`.

Люди приходять у робочий простір і залишають його через **Members** у [консолі акаунта]({{ACCOUNT_BASE_URL}}/members): там їх запрошують і там же вилучають. Цей API читає й оновлює їхні записи користувачів.

Оновлення й далі приймає `password`, але ні дашборд, ні застосунки ніколи його не питають: вони виконують вхід людей через їхній акаунт NimbusNexus. Пароль ніколи не повертається: запис користувача містить лише `id`, `name`, `description` і `enabled`.

Окремої дії «вимкнути», відмінної від «видалити», немає. Якщо потрібне мʼяке вимкнення (зберегти історію аудиту, заборонити вхід), встановіть `enabled: false` через оновлення — це і є шлях мʼякого вимкнення. Видалення — це остаточне видалення + відкликання всього.

## Чого робити не можна {#cant-do}

- **Створювати користувача.** `POST /api/v1/users` відповідає `403 Forbidden`. Користувач, створений через API, не мав би акаунта NimbusNexus, щоб увійти, тож запрошуйте людей у консолі акаунта.
- **Переносити користувача в інший робочий простір.** Запросіть людину в інший робочий простір через **Members** у консолі акаунта й надайте їй там потрібні ролі. У межах одного робочого простору переносити нічого: надайте користувачу роль в іншому проєкті.
- **Отримувати користувача з іншого робочого простору.** Отримання знаходить лише користувачів робочого простору того, хто здійснює виклик. Для будь-кого іншого API відповідає `404`.
