# Заплановані бекапи

[Бекапи](/docs/api/backups) на вимогу покривають випадок «мені потрібен снапшот цього тому просто зараз». Заплановані бекапи покривають усе інше: нічні бекапи кожного продакшн-тому, щотижневі повні бекапи в парі зі щоденними інкрементними, щомісячні снапшоти, які зберігаються рік для відповідності вимогам.

Розклад — це невеликий JSON-документ: оберіть ціль (том, VM, базу даних), частоту (у стилі cron), політику зберігання (зберігати N найновіших або видаляти через X днів) і політику сховища (регіон/клас сховища для бекапів). Планувальник працює у фоновому режимі; невдалі запуски повторюються з backoff і відображаються в журналі запусків розкладу.

Більшість продакшн-акаунтів використовують 2–4 розклади: щоденний зі зберіганням 14, щотижневий зі зберіганням 8, щомісячний зі зберіганням 12 і зрідка снапшот на кінець року, який зберігають 7 років для фінансових/юридичних потреб.
