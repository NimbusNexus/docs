# Балансувальники навантаження

Балансувальник навантаження стоїть перед парком VM з єдиним VIP (віртуальним IP), розподіляє трафік між бекендами й автоматично виводить несправні з ротації. Два види: **L4** (TCP / UDP / proxy-protocol) і **L7** (HTTP / HTTPS з маршрутизацією за шляхом + заголовками).

## Чотири вкладені ресурси {#sub-resources}

Сам балансувальник навантаження — це контейнер; логіка маршрутизації міститься у вкладених ресурсах:

- **Прослуховувач** — по одному на кожну пару (протокол, порт), на якій LB приймає трафік. `HTTPS:443` — один прослуховувач; `HTTP:80` — інший. Один LB може мати багато прослуховувачів.
- **Пул** — група бекенд-VM, визначена для кожного прослуховувача. Кожен пул має алгоритм (`round-robin`, `least-connections`, `source-ip-hash`) і політику збереження сесій.
- **Учасник пулу** — один бекенд у пулі. Посилається на VM + порт + вагу.
- **Монітор стану** — активна перевірка стану для кожного пулу. Учасників, що не пройшли перевірку, виводять із ротації, доки вони не відновляться.

Ендпоінти нижче працюють із балансувальником навантаження верхнього рівня. CRUD для вкладених прослуховувачів/пулів/учасників/моніторів стану розташовано за адресою `/v1/load-balancers/{id}/listeners` тощо (у цьому мінімальному прикладі їх немає — вони описані в актуальній специфікації).

## Термінація SSL {#ssl}

Для прослуховувачів HTTPS є два варіанти:

- **TLS термінується на LB.** Завантажте сертифікат (або використайте Let's Encrypt через доповнення cert-manager), і LB обслуговуватиме TLS для клієнтів, а з вашими VM спілкуватиметься відкритим текстом. Простіше в керуванні; дає LB змогу аналізувати HTTP-заголовки для маршрутизації L7.
- **Наскрізний TLS.** LB лише пересилає TCP на рівні L4; TLS обробляють ваші VM. Потрібно, коли бекенд має бачити оригінальний сертифікат клієнта.

## Перевірки стану {#health-checks}

Монітор стану періодично перевіряє кожного учасника (за замовчуванням кожні 10 секунд) на налаштованому шляху / порту. Три можливі результати:

- **Healthy** (справний) — останні 2 перевірки пройшли успішно (за замовчуванням; налаштовується). Учасник отримує трафік.
- **Unhealthy** (несправний) — останні 3 перевірки не пройшли (налаштовується). Учасника виведено з ротації; поточні зʼєднання поступово завершуються.
- **Recovering** (відновлюється) — був несправним, але знову проходить перевірки. Після 2 успішних перевірок стає справним.

Для перевірок стану через HTTP LB надсилає GET на `/healthz` (налаштовується) і очікує 200. Реалізуйте у своєму застосунку `/healthz`, який швидко повертає відповідь, — і не змушуйте перевірку виконувати реальну роботу, інакше сама перевірка стане навантаженням.

## Ціни {#pricing}

Балансувальники навантаження тарифікуються за фіксованою погодинною ставкою в кожному регіоні (\$0,024/год для стандартного рівня в довіднику цін EN). Створення прослуховувачів / пулів / учасників / моніторів стану безкоштовне. Трафік між LB у різних регіонах вважається стандартним міжрегіональним egress.
