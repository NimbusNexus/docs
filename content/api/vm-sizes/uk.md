# Розміри VM

Розмір VM — це іменована обчислювальна конфігурація: кількість vCPU, RAM, розмір кореневого диска й сімейство. Кожна VM створюється з кодом розміру (напр., `gp-4-16`); зміна розміру VM замінює код під час роботи.

## Чотири сімейства {#families}

| Сімейство | Префікс коду | Для чого оптимізоване |
| --- | --- | --- |
| **Загального призначення** | `gp-*` | Збалансовані CPU + RAM. Варіант за замовчуванням для більшості навантажень. |
| **Оптимізовані для обчислень** | `co-*` | 2× CPU на долар порівняно з `gp`, удвічі менше RAM на долар. Підходять для сервісів, обмежених CPU, пакетних задач, кодування відео. |
| **Оптимізовані для памʼяті** | `mo-*` | Зворотний компроміс. Підходять для кешів у памʼяті, купи JVM, проміжних даних аналітики. |
| **GPU** | `gx-*` | Прискорювачі NVIDIA L4 / H100. Інференс ML, навчання, транскодування. |

## Схема іменування {#naming}

Коди розмірів мають формат `<family>-<vCPU>-<RAM_GB>`. Тобто:

- `gp-1-2` — 1 vCPU, 2 GB RAM, загального призначення (найменший корисний розмір, ~\$0,0145/vCPU·год)
- `gp-4-16` — 4 vCPU, 16 GB RAM, загального призначення
- `co-16-32` — 16 vCPU, 32 GB RAM, оптимізований для обчислень
- `mo-8-64` — 8 vCPU, 64 GB RAM, оптимізований для памʼяті
- `gx-4-32-l4` — 4 vCPU, 32 GB RAM, 1× GPU L4 (у розмірах GPU в кінці додається код прискорювача)

Ендпоінт каталогу повертає повний список з актуальними цінами для кожного розміру. Ціни трохи відрізняються між регіонами; відповідь містить таблицю цін для кожного регіону.

## Зміна розміру {#resizing}

VM може переходити між розмірами без повторного розгортання. Зміна розміру в межах одного сімейства відбувається наживо (без даунтайму). Зміна розміру між сімействами потребує циклу зупинки / запуску. Зміна розміру між архітектурами (напр., з `gp` на `gx`) — це видалення / повторне створення: API відхиляє прямий виклик зміни розміру, щоб неявна втрата даних стала явною.
