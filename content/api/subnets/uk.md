# Підмережі

Підмережа — це блок IP-адрес усередині [мережі](/docs/api/networks). VM підʼєднується до мережі через порт, а порт отримує адресу з однієї з підмереж цієї мережі.

## Розмір CIDR {#cidr}

CIDR вибирають під час створення. Типові розміри:

| Сценарій | CIDR |
| --- | --- |
| Тестування з однією VM | `/29` |
| Невеликий застосунок (≤ 20 VM) | `/27` |
| Середній застосунок (≤ 100 VM) | `/25` |
| Великий застосунок | `/24` |
| VPC на весь проєкт | `/16` |

Не кожна адреса блоку дістається VM: порти отримують адреси з `allocation_pools` підмережі.

Після створення CIDR підмережі не змінюється. `PUT /api/v1/subnet/{subnet_id}` змінює її `name`, `dns_nameservers`, `allocation_pools`, `gateway_ip` і `enable_dhcp`, але не розмір; щоб отримати більше адрес, додайте до мережі ще одну підмережу. Зменшити підмережу, не створивши її заново, **не можна**: наявним VM довелося б змінити IP-адреси.

## DHCP, SLAAC і поведінка шлюзу {#dhcp}

- **Підмережі IPv4** за замовчуванням використовують DHCP. Кожна VM отримує фіксовану адресу з доступного діапазону підмережі. Якщо потрібна стабільна адреса (напр., для бекенда LB у DNS), конкретні IP можна заздалегідь виділити через ендпоінт портів.
- **Підмережі IPv6** приймають ті самі поля, що й підмережі IPv4, з `ip_version: 6`. Поля для вибору SLAAC чи DHCPv6 немає.
- **Шлюз** задається для кожної підмережі. Для підмереж тенанта, яким потрібен доступ до інтернету, шлюз вказує на [маршрутизатор](/docs/api/routers), підʼєднаний до підмережі.

## Кілька підмереж в одній мережі {#multiple}

До однієї мережі можна підʼєднати кілька підмереж. Так налаштовують подвійний стек IPv4 + IPv6: одна підмережа v4 і одна підмережа v6 в одній мережі.
