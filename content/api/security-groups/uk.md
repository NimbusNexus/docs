# Групи безпеки

Групи безпеки — це набори правил **фаєрвола з відстеженням стану**. Ви підʼєднуєте одну або кілька груп до мережевого інтерфейсу VM; застосовується обʼєднання правил усіх груп. Поведінка за замовчуванням: **заборонити весь вхідний трафік, дозволити весь вихідний** — явний список дозволеного для вхідного трафіку, а вихідний відкритий, доки ви не вирішите інакше.

## Що означає «з відстеженням стану» {#stateful}

Ви пишете правила лише для напрямку, у якому **ініціюється** зʼєднання. Якщо ви дозволили вхідний TCP на порт 443, пакети відповіді клієнту дозволяються автоматично — окреме правило для вихідного зворотного трафіку не потрібне.

Порівняйте з ACL без відстеження стану (напр., AWS Network ACLs), де потрібні симетричні правила в обох напрямках. З групами безпеки простіше міркувати про фаєрвол на рівні застосунку; з ACL без відстеження стану простіше міркувати про політики мережі тенанта на рівні нижче VM.

## Будова правила {#rules}

Кожне правило має:

- **Напрямок** — `ingress` або `egress`
- **Протокол** — `tcp`, `udp`, `icmp` або `any`
- **Діапазон портів** — один порт (`80`), діапазон (`8000-9000`) або «будь-який»
- **Джерело / призначення** — CIDR-блок (`0.0.0.0/0`, `10.0.0.0/8`) АБО ідентифікатор іншої групи безпеки

Найважливіше знати про режим «джерело — інша група безпеки». Правило на кшталт «дозволити порт 5432 з `web-tier-sg`» дає кожній VM у групі `web-tier-sg` змогу звертатися до вашої VM з Postgres на порт 5432 — без потреби перелічувати IP, і правило продовжує працювати, коли VM додаються до `web-tier-sg` або вилучаються з неї під час масштабування.

## Поширений патерн {#pattern}

Для трирівневого вебзастосунку:

1. **`web-tier-sg`** — вхідний трафік: дозволити `tcp/80` і `tcp/443` з `0.0.0.0/0` (публічно)
2. **`app-tier-sg`** — вхідний трафік: дозволити `tcp/8080` з `web-tier-sg` (лише вебрівень може звертатися до рівня застосунку)
3. **`db-tier-sg`** — вхідний трафік: дозволити `tcp/5432` з `app-tier-sg` (лише рівень застосунку може звертатися до бази даних)

Це добре поєднується: можна додати 4-ту групу для операційного VPN, яка дозволяє SSH з IP вашого офісу, і підʼєднати її разом із `db-tier-sg` до VM бази даних, не чіпаючи правил застосунку.
