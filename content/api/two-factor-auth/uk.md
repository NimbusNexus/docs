# Двофакторна автентифікація

Двофакторна автентифікація додає другий фактор (код TOTP із застосунку-автентифікатора) до входу за паролем. Ендпоінти тут вмикають її, показують її стан і вимикають:

- `GET /api/v1/2fa/credential` — генерує секрет TOTP і повертає його QR-код як зображення. Сам секрет надходить у заголовку відповіді `X-Secret-Key`.
- `POST /api/v1/2fa/totp_passcode_validation` — надішліть цей секрет як `secretKey` разом із поточним шестизначним `passcode` із застосунку. Якщо код збігається, 2FA вмикається.
- `GET /api/v1/2fa/status` — `two_factor_enabled` показує, чи ввімкнено 2FA.
- `POST /api/v1/2fa/off` — вимикає 2FA.

Кожен користувач має один секрет TOTP; повторне підключення його замінює.

Користувачі дашборду налаштовують 2FA у браузері на сторінці налаштувань акаунта. Через API кожен виклик читає чи змінює лише власну 2FA того, хто ввійшов і здійснює виклик, і ніколи — чужу. Тим, хто викликає API з API-ключем, 2FA не потрібна — ключі самі є фактором «те, що ви маєте».

Наполегливо рекомендуємо: увімкніть 2FA для кожного акаунта людини, що має ролі в продакшн-проєктах. Більшість компрометацій акаунтів спричинені повторним використанням паролів + відсутністю другого фактора.
