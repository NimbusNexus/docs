# SSH-ключі

SSH-ключі — це спосіб входити у VM з Linux після їх завантаження. Зареєструйте ключ для свого користувача, а потім укажіть його в `sshs` під час створення VM; cloud-init запише його у `~/.ssh/authorized_keys` користувача за замовчуванням.

## Як це працює {#how-it-works}

Зареєструвати ключ можна двома способами:

- `POST /api/v1/ssh/add_public` з `name` і вашим `ssh_public_key`. Ви надсилаєте лише **публічний** ключ; приватний залишається у вас.
- `POST /api/v1/ssh/` з `name` генерує пару ключів і один раз повертає її `private_key`. Збережіть його одразу: API більше ніколи його не покаже.

VM отримує той один ключ, який ви вказали в `sshs` під час її створення. Під час завантаження сервіс метаданих передає cloud-init цей публічний ключ, і cloud-init записує його у файл authorized_keys користувача за замовчуванням.

Ключі, додані **після** завантаження VM, не надсилаються на запущені VM автоматично. VM зберігає ключ, з яким її створено, тож новий ключ додайте всередині VM за допомогою свого звичного інструменту керування конфігурацією.

## Підтримувані формати {#formats}

Рядок ключа має бути у форматі OpenSSH: один рядок, що починається з `ssh-ed25519`, `ecdsa-sha2-nistp...` або `ssh-rsa`, далі йде ключ у кодуванні base64 і, за бажанням, коментар. Саме це за замовчуванням містять файли `~/.ssh/id_*.pub`.

## Відбитки + дублікати {#fingerprints}

Кожен ключ має стабільний **відбиток SHA256**. `GET /api/v1/ssh/` перелічує ваші ключі з їхніми `fingerprint` і публічним `key`. Назви ключів мають бути унікальними серед ваших ключів: на спробу зареєструвати другий ключ під назвою, яку ви вже використовуєте, API відповідає `409`.

## Видалення ключа {#removing}

`DELETE /api/v1/ssh/` з ID ключа в `ssh_keys` видаляє його, тож нові VM не зможуть ним скористатися. **Уже завантажені VM зберігають ключ** у своєму файлі authorized_keys — cloud-init не узгоджує стан, а лише встановлює налаштування під час першого завантаження. Щоб відкликати ключ на запущених VM, зробіть одне з двох:

1. Створіть VM заново з іншим ключем у `sshs` або
2. Відредагуйте `~/.ssh/authorized_keys` безпосередньо всередині VM (або через свій інструмент керування конфігурацією).
