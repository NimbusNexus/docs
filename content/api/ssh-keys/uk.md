# SSH-ключі

SSH-ключі — це спосіб входити у VM з Linux після їх завантаження. Зареєструйте свій публічний ключ у проєкті, і cloud-init додасть його у `~/.ssh/authorized_keys` користувача за замовчуванням на кожній новій VM.

## Як це працює {#how-it-works}

Ви реєструєте лише **публічний** ключ — NimbusNexus ніколи не бачить вашого приватного ключа. Під час завантаження сервіс метаданих передає cloud-init зареєстровані публічні ключі проєкту, і cloud-init записує їх у файл authorized_keys користувача за замовчуванням (`ubuntu` в Ubuntu, `debian` у Debian, `rocky` у Rocky, `Administrator` для Windows через WinRM).

Ключі, додані **після** завантаження VM, не надсилаються на запущені VM автоматично. Або перезавантажте VM (за замовчуванням cloud-init запускається лише під час першого завантаження, тож це допоможе тільки з образами, у яких увімкнено повторний запуск), або додайте ключ усередині VM за допомогою свого звичного інструменту керування конфігурацією.

## Підтримувані формати {#formats}

Ми приймаємо:

- **ed25519** — рекомендовано; компактний, швидкий, сучасний
- **ecdsa-sha2-nistp256 / nistp384 / nistp521**
- **RSA** — мінімум 2048 біт; рекомендовано 4096 біт; ключі < 2048 ми відхиляємо

DSA відхиляється (в upstream він застарілий ще з OpenSSH 7.0).

Рядок ключа має бути у форматі OpenSSH: один рядок, що починається з `ssh-ed25519`, `ecdsa-sha2-nistp...` або `ssh-rsa`, далі йде ключ у кодуванні base64 і, за бажанням, коментар. Саме це за замовчуванням містять файли `~/.ssh/id_*.pub`.

## Відбитки + дублікати {#fingerprints}

Кожен ключ має стабільний **відбиток SHA256**. API відхиляє дублікати за відбитком — повторне додавання того самого ключа (навіть з іншою міткою) повертає 409. Так поширена помилка «я додав ключ свого ноутбука у два проєкти» виявляється, перш ніж вона призведе до плутанини з тим, якому акаунту належить ключ.

## Видалення ключа {#removing}

Видалення ключа з проєкту прибирає його з майбутніх завантажень VM. **Уже завантажені VM зберігають ключ** у своєму файлі authorized_keys — cloud-init не узгоджує стан, а лише встановлює налаштування під час першого завантаження. Щоб відкликати ключ на запущених VM, зробіть одне з двох:

1. Створіть VM заново зі свіжого снапшота або
2. Відредагуйте `~/.ssh/authorized_keys` безпосередньо всередині VM (або через свій інструмент керування конфігурацією).

Якщо ключ скомпрометовано й відкликати його треба швидко: у дашборді є дія «revoke from all projects» в один клік, яка надсилає видалення через сервіс метаданих. Відповідник в API буде в довіднику IAM (незабаром).
