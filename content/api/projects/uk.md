# Проєкти

Проєкт — це **одиниця ізоляції** в NimbusNexus для ресурсів, білінгу й керування доступом. Кожен ресурс (VM, том, bucket, база даних, мережа, …) належить рівно одному проєкту; кожен API-ключ привʼязаний рівно до одного проєкту; кожна позиція рахунку стосується рівно одного проєкту.

## Чому проєкти важливі {#why}

Межа проєкту дає вам три гарантії:

1. **Радіус ураження.** Скомпрометований API-ключ проєкту `dev` не може зачепити ресурси `prod`. Їх буквально не видно зсередини `dev`.
2. **Розподіл витрат.** Кожен проєкт отримує власний рахунок. Якщо фінансовий відділ хоче виставляти маркетингу рахунок за хостинг вебсайту, маркетинг отримує проєкт. Якщо інженерний відділ хоче розподіляти витрати за командами, кожна команда отримує проєкт.
3. **Квота.** Квоти діють на рівні проєкту. Проєкт, який безконтрольно створює VM, не вичерпує запасу іншого проєкту.

## Ієрархія проєктів {#hierarchy}

Проєкти можуть мати батьківський проєкт (на рівні organization і вище). Ієрархія виглядає так:

```text
acme-org (root)
├── acme-prod
├── acme-staging
└── acme-dev
```

Користувач із роллю `admin` в `acme-org` автоматично успадковує права адміністратора в кожному дочірньому проєкті. Користувач, який має права адміністратора лише в `acme-prod`, не бачить `acme-staging` чи `acme-dev`. Це стандартний механізм для схеми «централізоване керування, децентралізована щоденна робота».

Ієрархія необовʼязкова. Акаунти базового рівня отримують один кореневий проєкт на акаунт; акаунти рівня organization можуть будувати дерева глибиною до 5 рівнів.

## Що міститься в проєкті {#contents}

- VM, томи, снапшоти, бекапи
- Bucket-и, архіви
- Бази даних
- Мережі, підмережі, маршрутизатори, групи безпеки, плаваючі IP, балансувальники навантаження
- DNS-зони + записи
- Користувачі, ролі + призначення ролей, API-ключі
- Платіжний акаунт, який оплачує все перелічене вище

Проєкти не можна обʼєднувати. Щоб звести два проєкти в один, доведеться експортувати й заново імпортувати ресурси, а потім видалити вихідний проєкт. Атомарної операції обʼєднання навмисно немає: відстежити під час аудиту, «що куди обʼєднали», було б неможливо.

## Видалення {#deletion}

`DELETE /v1/projects/{id}` — **руйнівна й незворотна** операція. Кожен ресурс у проєкті знищується: VM, томи, снапшоти, бекапи, bucket-и, бази даних, DNS-зони — усе. Записи користувачів і призначення ролей атомарно відкликаються.

З міркувань безпеки API вимагає для цього виклику заголовок підтвердження (`X-Confirm-Project-Delete: <project-id>`); без нього запит повертає 400.
