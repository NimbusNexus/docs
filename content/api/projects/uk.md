# Проєкти

Проєкт — це **одиниця ізоляції** в NimbusNexus для ресурсів і керування доступом. Кожен проєкт належить до одного [робочого простору](/docs/api/workspaces). Кожен ресурс (VM, том, bucket, мережа, …) належить рівно одному проєкту, а кожен API-ключ привʼязаний рівно до одного проєкту. Білінг ведеться на рівні робочого простору: один рахунок охоплює всі його проєкти.

## Чому проєкти важливі {#why}

Межа проєкту дає вам дві гарантії:

1. **Радіус ураження.** Скомпрометований API-ключ проєкту `dev` не може зачепити ресурси `prod`. Їх буквально не видно зсередини `dev`.
2. **Квота.** Квоти діють на рівні проєкту. Проєкт, який безконтрольно створює VM, не вичерпує запасу іншого проєкту.

## Створення проєкту {#create}

`POST /api/v1/projects/` приймає ID робочого простору в `domain_id`, `project_name` і, за бажанням, `project_description` та `enabled`. Назва має бути унікальною в робочому просторі, інакше API відповідає `409`. Робочий простір може мати ліміт на кількість проєктів; понад нього створення відповідає `403`.

Проєкти стоять у своєму робочому просторі поруч один з одним. Вкласти один проєкт в інший через API не можна.

## Що міститься в проєкті {#contents}

- VM, томи, бекапи
- Bucket-и
- Мережі, підмережі, маршрутизатори, групи безпеки, плаваючі IP, балансувальники навантаження
- DNS-зони + записи
- Призначення ролей і API-ключі (користувачі, яким вони належать, існують у робочому просторі)

Проєкти не можна обʼєднувати. Щоб звести два проєкти в один, доведеться експортувати й заново імпортувати ресурси, а потім видалити вихідний проєкт. Атомарної операції обʼєднання навмисно немає: відстежити під час аудиту, «що куди обʼєднали», було б неможливо.

## Видалення {#deletion}

`DELETE /api/v1/projects/` приймає `id` проєкту в тілі запиту, і це **незворотна** операція. Вона видаляє стандартну мережу проєкту, а потім сам проєкт і його призначення ролей. Більше нічого вона не видаляє, тож спершу видаліть VM, томи, bucket-и та інші ресурси проєкту.
