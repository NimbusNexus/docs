# Робочі простори

**Робочий простір** — це верхній рівень ізоляції в моделі акаунтів NimbusNexus. Кожен проєкт належить рівно одному робочому простору; доступ кожного користувача обмежено робочими просторами (і конкретними проєктами в них). Ієрархія така: **робочий простір → проєкт → ресурс**.

Більшості акаунтів достатньо одного робочого простору. Більші організації використовують кілька робочих просторів, щоб розділити білінг, доступ і ліміти ресурсів на рівні організаційних підрозділів — напр., один робочий простір на кожен бізнес-підрозділ або на кожну юридичну особу. Білінг ведеться окремо для кожного робочого простору, а доступ перетинає межу робочого простору, лише коли ви самі її відкриваєте: запрошуєте когось усередину або надаєте іншому проєкту спільний доступ до мережі чи DNS-зони.

Не плутайте робочий простір із DNS-зоною — у деяких контекстах це те саме слово (OpenStack називає робочі простори «доменами»). API зберігає слово OpenStack: шляхи ендпоінтів робочих просторів починаються з `/api/v1/domains/`, а в назвах їхніх полів теж стоїть domain (`domain_id`, `domain_name`, `domain_description`).
