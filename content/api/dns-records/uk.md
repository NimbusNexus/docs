# DNS-записи

Набір записів — це один кортеж `(name, type)` у [зоні](/docs/api/dns-zones), що містить одне або кілька значень. `www.example.com → A → 203.0.113.5` — це набір записів A з одним значенням; набори з кількома значеннями (round-robin DNS) містять N значень під одним ідентифікатором набору.

## Підтримувані типи записів {#types}

| Тип | Призначення | Приклад значення |
| --- | --- | --- |
| **A** | Адреса IPv4 | `203.0.113.5` |
| **AAAA** | Адреса IPv6 | `2001:db8::1` |
| **CNAME** | Псевдонім для іншого імені | `other.example.com.` |
| **MX** | Поштовий сервер | `10 mail.example.com.` |
| **TXT** | Довільний текст — верифікація, SPF, DKIM, DMARC | `"v=spf1 -all"` |
| **SPF** | Політика SPF в окремому типі запису | `"v=spf1 -all"` |
| **SRV** | Розташування сервісу | `10 5 5060 sip.example.com.` |
| **NS** | Делегування іншим серверам імен | `ns1.other.com.` |
| **CAA** | Дозвіл для центрів сертифікації | `0 issue "letsencrypt.org"` |
| **SSHFP** | Відбиток ключа SSH-хоста | `4 2 <sha256-fingerprint>` |
| **NAPTR** | Правило перезапису для пошуку сервісу | `100 10 "U" "E2U+sip" "!^.*$!sip:info@example.com!" .` |
| **PTR** | Вказівник зворотного DNS | Див. [зворотний DNS](/docs/api/reverse-dns) |

Ми не підтримуємо `ALIAS` / `ANAME` (CNAME-flattening на кореневому домені) — натомість використовуйте CNAME на піддомені або запис A, що вказує на плаваючий IP, на кореневому домені.

## Записи з кількома значеннями {#multi-value}

В один набір записів можна помістити кілька значень:

```text
www.example.com → A → 203.0.113.5
                  → 203.0.113.6
                  → 203.0.113.7
```

Сервери імен віддають усі три значення на кожен запит, а резолвери розподіляють запити між ними — це базове балансування навантаження round-robin без LB. Для повноцінного балансування натомість націльте запис на VIP [балансувальника навантаження](/docs/api/load-balancers); кілька значень підходять для випадків, коли клієнт і резолвер можуть самі впоратися з failover (більшість сучасних HTTP-клієнтів це вміють).

## TTL {#ttl}

Кожен набір записів має TTL у секундах — скільки резолвери кешують відповідь, перш ніж запитати знову. Задайте `ttl`, коли створюєте або оновлюєте набір записів. Без нього набір записів бере TTL своєї зони: 3600 (1 година), хіба що ви задали для зони інше значення.

Поки ви активно вносите зміни, ставте менші TTL; коли записи стабілізуються, збільште їх, щоб зменшити кількість запитів.
