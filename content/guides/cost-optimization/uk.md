# Оптимізація місячного рахунку

Якщо ваш рахунок NimbusNexus більший, ніж очікувалося, то, з нашого досвіду, 90 % перевитрат припадає на ті самі пʼять місць. Щоб пройти їх по черзі, потрібно близько 30 хвилин, і зазвичай це скорочує рахунок на 30–60 %.

Порядок має значення — спершу найдієвіші кроки.

## 1 · Забуті зупинені VM {#stopped-vms}

Зупинені VM досі коштують ~10 % від вартості роботи (ви платите за диск і зарезервований IP). Три місяці зупиненої `gp-8-32` коштують приблизно стільки ж, скільки місяць роботи такої VM.

Знайдіть їх:

```bash
curl "{{API_BASE_URL}}/v1/vms?state=stopped" \
  -H "Authorization: Bearer $NIMBUS_KEY" \
  | jq '.items[] | { id, name, stopped_at, size }'
```

Для кожної вирішіть:

- **Зупинена < 1 тижня тому, і ви памʼятаєте чому** → не чіпайте, це кандидат для відкату.
- **Зупинена > 2 тижнів тому, не памʼятаєте чому** → зробіть снапшот (щоб зберегти образ диска), потім `DELETE`.
- **Зупинена > 1 місяця тому** → видаліть. Що б на ній не було, для відкату це вже не годиться.

```bash
# Snapshot first
curl -X POST {{API_BASE_URL}}/v1/snapshots \
  -H "Authorization: Bearer $NIMBUS_KEY" \
  -H "Content-Type: application/json" \
  -d "{ \"source_vm_id\": \"$VM_ID\", \"name\": \"archive-$(date +%Y-%m-%d)\" }"

# Then delete the VM
curl -X DELETE {{API_BASE_URL}}/v1/vms/$VM_ID \
  -H "Authorization: Bearer $NIMBUS_KEY"
```

Снапшот набагато дешевший за зупинену VM (зберігання снапшотів коштує $0,04/GB; зарезервовані IP і диск зупиненої VM коштують більше).

## 2 · Непідʼєднані плаваючі IP {#unattached-ips}

Кожен непідʼєднаний плаваючий IP коштує $2,50/міс — стільки ж, скільки IP, підʼєднаний до зупиненої VM. Позиція в рахунку за один IP невелика, але в акаунтах, що існують уже давно, такі IP накопичуються.

```bash
curl "{{API_BASE_URL}}/v1/floating-ips?state=detached" \
  -H "Authorization: Bearer $NIMBUS_KEY" \
  | jq '.items[] | { id, ipv4, region, allocated_at }'
```

Звільніть кожен, який ви активно не використовуєте:

```bash
curl -X DELETE {{API_BASE_URL}}/v1/floating-ips/$IP_ID \
  -H "Authorization: Bearer $NIMBUS_KEY"
```

Якщо пізніше вам може знадобитися та сама IPv4-адреса (бо десь вона в списку дозволених), перед звільненням запишіть, які IP були вашими. Ми не резервуємо звільнені IP — вони повертаються в регіональний пул. «Заморозити» IP, не тримаючи його виділеним, неможливо.

## 3 · VM із надлишковими ресурсами {#over-provisioned}

За VM, що весь час працює на 5–10 % CPU, ви платите 10× від того, що їй потрібно. Запустіть `node_exporter` (або просто перегляньте графік VM у дашборді) і знайдіть VM, у яких P99 CPU за 90 днів нижчий за ~30 %.

Що робити з кожною такою VM, залежить від характеру трафіку:

- **Стабільно низький трафік** → зменште розмір. `POST /v1/vms/$ID/resize` на менший рівень. Займає ~30 секунд. Зміна розміру наживо підтримується в межах одного сімейства (`gp-4-16` → `gp-2-8` працює; `gp-4-16` → `co-4-8` вимагає зупинки, зміни розміру й запуску, бо змінюється архітектура).
- **Трафік зі сплесками** → розгляньте розміри, оптимізовані для обчислень (сімейство `co-`); у них вище співвідношення CPU/RAM. Дешевше за vCPU для навантажень, обмежених CPU.
- **GPU-VM, у яких GPU простоює** → повністю перейдіть із сімейства `gx-` на інше. GPU-VM у 5–10× дорожчі; якщо ви не використовуєте GPU, ви спалюєте гроші.

## 4 · Невідповідний клас обʼєктного сховища {#storage-class}

В обʼєктному сховищі є три класи:

| Клас | Ціна зберігання | Ціна отримання | Для чого |
|---|---|---|---|
| Standard | $0,013/GB·міс | Безкоштовно | Гарячі дані (часто читаються) |
| Infrequent Access (IA) | $0,007/GB·міс | $0,005/GB | Теплі дані (читаються щомісяця) |
| Cold | $0,004/GB·міс | Вища, залежить від класу (Expedited, Standard, Bulk) | Архів (читається рідко) |

Більшість акаунтів за замовчуванням тримають усе в Standard і ніколи цього не переглядають. Де тут можна зекономити:

```bash
# What buckets do you have, and what class?
curl {{API_BASE_URL}}/v1/buckets \
  -H "Authorization: Bearer $NIMBUS_KEY" \
  | jq '.items[] | { name, region, storage_class, size_gb }'
```

Для кожного bucket-а перегляньте timestamp останнього доступу до найбільших обʼєктів (його показує «object explorer» у дашборді). Усе, що не читалося останній місяць, варто перевести в IA; усе, що не читалося 6 місяців, імовірно, — у Cold.

Переносити обʼєкти вручну по одному не потрібно — задайте правило життєвого циклу:

```bash
curl -X PUT {{API_BASE_URL}}/v1/buckets/$BUCKET/lifecycle \
  -H "Authorization: Bearer $NIMBUS_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "rules": [
      {
        "id": "tier-warm",
        "filter": { "prefix": "archive/" },
        "transitions": [
          { "after_days": 30,  "storage_class": "infrequent-access" },
          { "after_days": 180, "storage_class": "cold" }
        ]
      }
    ]
  }'
```

Так дані автоматично переходять на дешевші рівні в міру старіння. Найвигідніше для навантажень типу «створюю ці дані один раз і рідко перечитую» (логи, артефакти збірок, старі звіти).

## 5 · Непотрібні снапшоти {#stale-snapshots}

Снапшоти коштують $0,04 за GB·міс — набагато дешевше, ніж диск VM, але вони швидко накопичуються, якщо робити їх щоночі й ніколи не видаляти. Снапшот на 200 GB, який зберігається рік, коштує $96.

```bash
curl "{{API_BASE_URL}}/v1/snapshots?older_than_days=180" \
  -H "Authorization: Bearer $NIMBUS_KEY" \
  | jq '.items[] | { id, name, size_gb, created_at, source_vm_id }'
```

Три емпіричні правила зберігання снапшотів:

- **Щоденні снапшоти** продакшн-VM → зберігайте 14, решту видаляйте.
- **Щотижневі снапшоти** → зберігайте 8 (два місяці).
- **Щомісячні снапшоти** → зберігайте 12 (один рік). Із давніших залишайте лише ті, що зроблені наприкінці року.

Налаштуйте [політику запланованих бекапів](/docs/api/backups) із цими правилами зберігання, щоб кількість снапшотів більше ніколи не зростала безконтрольно.

## Нагадування про модель цін {#reminders}

Кілька моментів, на яких часто спотикаються нові клієнти:

- **Трафік між ресурсами NimbusNexus у межах регіону безкоштовний.** Дві VM у `us-east-1`, що обмінюються даними, не платять за egress. Міжрегіональний трафік між ресурсами NimbusNexus теж безкоштовний (навмисна відмінність від AWS, де це найнесподіваніша позиція в рахунку).
- **Вихідний трафік в інтернет коштує $0,01/GB після перших 100 GB на місяць.** Порівняно з AWS (де це $0,09/GB) це важливо, щойно ви віддаєте хоч скільки-небудь помітний обсяг публічного контенту.
- **Посекундна тарифікація VM.** VM, що працює 90 секунд, коштує як 1,5 хвилини. Жодного округлення до години. Тож короткі навантаження (CI-раннери, пакетні завдання) справді дешеві — не ускладнюйте систему заради «мінімізації запусків», якщо запуски короткі.
- **Стартовий кредит одноразовий.** Нові акаунти отримують кредит; він не поповнюється. Якщо ви багато тестуєте, стежте за балансом кредиту в дашборді.

## Аналіз самого рахунку {#invoice}

Сторінка білінгу в дашборді розбиває позиції рахунку за ресурсами й днями. Фільтр «top 10 costs» — правильна відправна точка, якщо ви ще не знаєте, що саме дороге, — майже завжди це одна-дві непропорційно великі позиції, а не «смерть від тисячі порізів».

Якщо вам потрібен рахунок у форматі JSON:

```bash
curl {{API_BASE_URL}}/v1/billing/invoices/current \
  -H "Authorization: Bearer $NIMBUS_KEY"
```

У відповіді є прогноз витрат за кожним ресурсом до кінця місяця, тож ви можете реагувати на те, що дороге *зараз*, а не виявляти це наприкінці місяця.
