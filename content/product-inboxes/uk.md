# Inboxes

NimbusNexus Inboxes дає вам одноразові **поштові адреси**, що приймають справжні листи. Ви створюєте адресу, націлюєте на неї форму реєстрації чи набір тестів і читаєте, що надійшло, у консолі або через REST API.

> **Не та сторінка?** Inboxes лише отримує пошту. Якщо вам треба *надсилати* листи зі свого застосунку, цей продукт не підходить. Щоб перехоплювати **HTTP-запити** — вебхуки провайдера чи те, що надсилає ваш власний застосунок, — використовуйте [Request Bins](/docs/product-bins).

## Коротко {#at-a-glance}

| | |
| --- | --- |
| Що ви створюєте | **Скринька**: одноразова поштова адреса |
| Базовий URL API | `{{INBOXES_BASE_URL}}` |
| Автентифікація | `Authorization: Bearer <key>`, ключ, випущений у консолі акаунта для продукту **Inboxes** |
| Ідентифікатор, який приймає кожен маршрут | `id` скриньки, напр. `inb_7f820a77f64ea18174499945`, — ніколи не адреса |
| Як знайти скриньку за адресою | `GET /v1/inboxes?address=<address>` |
| Як прочитати, що надійшло | `GET /v1/inboxes/{id}/messages` або `GET /v1/messages` для всіх скриньок одразу (платні плани; на безкоштовному — у консолі) |
| Як шукати серед того, що надійшло | `q` у будь-якому з двох списків; `in` або `header` звужують пошук ([Пошук повідомлень](#search)) |
| Як видалити скриньку | `DELETE /v1/inboxes/{id}` — остаточно, і адреса більше ніколи не видається |
| Усі маршрути з прикладами | [Довідник API Inboxes](/docs/reference/inboxes) |

## Як це працює {#how}

1. **Створіть** скриньку — у консолі кнопкою **Create an inbox** або через `POST /v1/inboxes`.
2. **Надішліть** лист на її адресу із системи, яку тестуєте, з `phrase` скриньки в темі, якщо фраза є.
3. **Прочитайте**, що надійшло. Лист зʼявляється в консолі за кілька секунд, а на платних планах — і в `GET /v1/inboxes/{id}/messages`. Щоб знайти одне повідомлення серед багатьох, шукайте в темах, відправниках, заголовках і тілах: у консолі — **Search** над списком, в API — `q` ([Пошук повідомлень](#search)). **All inboxes** у консолі та `GET /v1/messages` в API показують список того, що надійшло в усі скриньки одразу.
4. **Видаліть** скриньку, коли закінчите, або дайте їй спливти.

Усі чотири кроки з `curl` показано на сторінці [Швидкий старт](/docs/product-inboxes/quickstart).

Використовуйте `address` саме в тому вигляді, у якому його повертає API. Адреси розміщені на окремому домені, а не на `{{ROOT_DOMAIN}}`, щоб одноразовий трафік ніколи не ділив репутацію з доменом, з якого йде ваша справжня пошта.

## Як працює приймання {#acceptance}

Пошта відхиляється одразу на вході, а не приймається й приховується. Повідомлення зберігається, лише якщо виконано всі ці умови:

- адреса отримувача — це активна, увімкнена скринька;
- **тема містить фразу цієї скриньки**, якщо фраза є;
- робочий простір не вийшов за межі свого місячного обсягу;
- повідомлення не більше за 5 MiB.

Усе інше відхиляється під час SMTP-сесії, тож сервер відправника дізнається про це й сам формує bounce. Відхилене повідомлення ніколи не зберігається й ніколи не зараховується до вашого споживання.

Прийнята пошта очищується перед збереженням: HTML проходить через санітайзер зі списком дозволеного, а консоль рендерить його в ізольованому фреймі, де віддалені зображення заблоковані, доки ви їх не запросите. Написати на одноразову адресу може будь-хто, тож вміст вважається написаним зловмисником.

## Як завершується скринька {#lifecycle}

| | Що відбувається | Чи можна скасувати? |
| --- | --- | --- |
| **Вимкнення** | Скринька перестає приймати пошту й зберігає те, що вже має; надіслані на неї листи відхиляються. | Так — увімкніть її знову |
| **Видалення** | Скриньку та її пошту видалено, а її адресу виведено з обігу: вона більше ніколи не видається ні вам, ні комусь іншому. | Ні |
| **Закінчення строку дії** | У момент `expires_at` — те саме, що й видалення. Строк дії кожної безкоштовної скриньки спливає щонайпізніше через 24 години; на платному плані він спливає лише в скриньки, створеної із заданим часом життя. | Ні |

У консолі меню ⋯ на сторінці скриньки містить **Rename…**, **Disable** або **Enable**, **Empty inbox…**, що видаляє її пошту, але зберігає скриньку, і **Delete inbox…**. Видалення — це `DELETE /v1/inboxes/{id}`; старіші версії цієї документації та журнал аудиту API називають його *release*. Адреса, виведена з обігу, навмисно ніколи не видається повторно: повторно використана адреса доставила б лист для скидання пароля незнайомця тому, хто отримав її наступним. Подробиці, зокрема як повʼязані закінчення строку дії та зберігання, — на сторінці [Адреси та фраза](/docs/product-inboxes/addresses#lifecycle).

## Читання через API {#reading}

Повідомлення можна читати в консолі на будь-якому плані, включно з безкоштовним. Читати їх **програмно** дають змогу платні плани: `GET /v1/inboxes/{id}/messages` повертає список повідомлень скриньки, найновіші першими, з відправником, темою й вердиктами автентифікації кожного, а з `extract=otp` — ще й поле `extracted` з одноразовим кодом, якщо ми його знайшли, — а зазвичай тесту потрібен лише він. `GET /v1/messages` повертає повідомлення всіх скриньок робочого простору одним списком, кожне зі своїм `inbox_id`. `GET /v1/inboxes/{id}/messages/{message_id}` повертає одне повідомлення повністю: обидві частини тіла, відомості про його вкладення та його [заголовки](#headers).

Кожен маршрут приймає `id` скриньки. Консоль показує його на сторінці скриньки поруч з **ID**, з кнопкою копіювання. Якщо у вас є лише адреса, знайдіть скриньку за нею:

```bash
curl "{{INBOXES_BASE_URL}}/v1/inboxes?address=ff25m3tue9vm@nninbox.com" \
  -H "Authorization: Bearer $INBOXES_API_KEY"
```

Відповідь — звичайний список щонайбільше з одним елементом. `GET /v1/inboxes` і `GET /v1/inboxes/{id}` повертають `id`, `address` і `phrase` разом, тож один виклик дає все потрібне, щоб надсилати й читати.

## Пошук повідомлень {#search}

Обидва списки повідомлень підтримують пошук: `GET /v1/inboxes/{id}/messages` — для однієї скриньки, а `GET /v1/messages` — для всіх. Поле **Search** над кожним списком у консолі надсилає ті самі параметри:

| Параметр | Що це |
| --- | --- |
| `q` | Лише повідомлення, що містять цей текст (до 200 символів, без урахування регістру). |
| `in` | Де шукає `q`: `all` (за замовчуванням) або лише `subject`, `from` (відправник, як його вказано в заголовку From), `headers` (кожен заголовок як `name: value`) чи `body` (текстове тіло, а для листа лише з HTML-тілом — текст його HTML). |
| `header` | Лише значення цього заголовка (його назва — у будь-якому регістрі); якщо заголовок надійшов кілька разів — будь-яке з них. Без `q` — кожне повідомлення, що містить цей заголовок. Поєднується з `in` `all` або `headers`. |

```bash
curl -G "{{INBOXES_BASE_URL}}/v1/inboxes/inb_7f820a77f64ea18174499945/messages" \
  --data-urlencode "q=verification code" \
  --data-urlencode "in=subject" \
  -H "Authorization: Bearer $INBOXES_API_KEY"
```

`since`, `until`, `extract` і `limit` працюють із пошуком так само, як і без нього. `header` з `in`, встановленим у `subject`, `from` або `body`, відхиляється з `422` `validation_error` із записом типу `inboxes.search_conflict`.

Пошук гортає сторінки інакше, ніж звичайний список. Він читає повідомлення від найновіших і зупиняється, коли знайде `limit` збігів або прочитає 16 MiB пошти (чи 5 000 повідомлень), залежно від того, що настане раніше, тож сторінка може містити менше збігів, ніж `limit`, або жодного, хоча старіші повідомлення ще не прочитано. Сторінка пошуку має `next_offset` `null` і, доки пошук не прочитає найстаріше повідомлення списку, `next_until`: передайте його назад як `until` з тим самим пошуком і `since`, щоб продовжити пошук з місця, де він зупинився. Під час пошуку параметр `offset` пропускає вказану кількість повідомлень, перш ніж пошук почне читати. Без пошуку `next_until` завжди дорівнює `null`, а список ділиться на сторінки за `next_offset`.

Пошук у заголовках знаходить лише пошту, що надійшла після того, як Inboxes почав зберігати заголовки ([Заголовки](#headers)).

## Заголовки {#headers}

`GET /v1/inboxes/{id}/messages/{message_id}` містить рядки заголовків листа в `headers`: обʼєкти з `name` і `value` у порядку надходження, з дублікатами; кожне значення розгорнуто в один рядок, а його закодовані слова (RFC 2047) декодовано. Зберігається до 256 рядків, назва обрізається до 256 символів, а значення — до 8 192. Списки повідомлень заголовків не містять. У консолі заголовки показано в розділі **Headers** повідомлення.

`headers` дорівнює `null` для листа, що надійшов до того, як Inboxes почав зберігати заголовки: для нього їх не збережено, і додати їх пізніше не можна. Сирий лист не зберігається — лише його розібрані частини.

## Як отримати доступ {#access}

Зареєструйтеся в Inboxes — і отримаєте робочий простір на безкоштовному плані: одна скринька одночасно, зберігання 24 години й читання в консолі. Ціни наведено на [сторінці Inboxes](/inboxes).

Ключі не видаються разом із робочим простором, і API Inboxes їх не випускає. Випустіть ключ у консолі акаунта NimbusNexus у розділі **API keys**, вибравши продукт **Inboxes**: API-ключі для всієї платформи випускає лише Identity. Ключ — це JWT, тож він починається з `eyJ`. Передавайте його як `Authorization: Bearer <key>` або `X-API-Key: <key>`.

Виберіть область дії під час випуску ключа: `admin` може створювати, змінювати, очищати й видаляти скриньки, а також читати, `read` може лише читати. Ключ Inboxes не можна обмежити одним проєктом.

> **Ключ `inbx_…` більше не проходить автентифікацію.** Раніше Inboxes випускав власні ключі з цим префіксом. Якщо у вас такий є, випустіть заміну в консолі акаунта.

## Чого продукт не робить {#not}

- **Він не надсилає.** API для надсилання чи ретрансляції немає. Адреса, з якої можна було б надсилати пошту, стала б спам-сервісом.
- **Це не архів.** Повідомлення видаляється, коли спливає строк зберігання плану, а все, що має адреса, зникає, коли адресу видаляють або коли вона спливає.
- **Він поки не пересилає.** Пересилання отриманого на ваш URL заплановано, але ще не реалізовано.
- **Він не перехоплює HTTP.** Скринька лише отримує пошту. Для вебхуків та інших HTTP-запитів використовуйте [Request Bins](/docs/product-bins): його URL-адреси записують будь-який надісланий на них запит.
