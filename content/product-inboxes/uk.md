# Inboxes

NimbusNexus Inboxes дає вам одноразові **поштові адреси**, що приймають справжні листи. Ви створюєте адресу, націлюєте на неї форму реєстрації чи набір тестів і читаєте, що надійшло, у консолі або через REST API.

> **Не та сторінка?** Inboxes лише отримує пошту. Якщо вам треба *надсилати* листи зі свого застосунку, цей продукт не підходить. Щоб перехоплювати **HTTP-запити** — вебхуки провайдера чи те, що надсилає ваш власний застосунок, — використовуйте [Request Bins](/docs/product-bins).

## Коротко {#at-a-glance}

| | |
| --- | --- |
| Що ви створюєте | **Скринька**: одноразова поштова адреса |
| Базовий URL API | `{{INBOXES_BASE_URL}}` |
| Автентифікація | `Authorization: Bearer <key>`, ключ, випущений у консолі акаунта для продукту **Inboxes** |
| Ідентифікатор, який приймає кожен маршрут | `id` скриньки, напр. `inb_7f820a77f64ea18174499945`, — ніколи не адреса |
| Як знайти скриньку за адресою | `GET /v1/inboxes?address=<address>` |
| Як прочитати, що надійшло | `GET /v1/inboxes/{id}/messages` (платні плани; на безкоштовному — у консолі) |
| Як видалити скриньку | `DELETE /v1/inboxes/{id}` — остаточно, і адреса більше ніколи не видається |
| Усі маршрути з прикладами | [Довідник API Inboxes](/docs/reference/inboxes) |

## Як це працює {#how}

1. **Створіть** адресу — у консолі кнопкою **New address** або через `POST /v1/inboxes`.
2. **Надішліть** на неї лист із системи, яку тестуєте, з `phrase` скриньки в темі, якщо фраза є.
3. **Прочитайте**, що надійшло. Лист зʼявляється в консолі за кілька секунд, а на платних планах — і в `GET /v1/inboxes/{id}/messages`.
4. **Видаліть** адресу, коли закінчите, або дайте їй спливти.

Усі чотири кроки з `curl` показано на сторінці [Швидкий старт](/docs/product-inboxes/quickstart).

Використовуйте `address` саме в тому вигляді, у якому його повертає API. Адреси розміщені на окремому домені, а не на `{{ROOT_DOMAIN}}`, щоб одноразовий трафік ніколи не ділив репутацію з доменом, з якого йде ваша справжня пошта.

## Як працює приймання {#acceptance}

Пошта відхиляється одразу на вході, а не приймається й приховується. Повідомлення зберігається, лише якщо виконано всі ці умови:

- адреса отримувача — це активна, увімкнена скринька;
- **тема містить фразу цієї скриньки**, якщо фраза є;
- робочий простір не вийшов за межі свого місячного обсягу;
- повідомлення не більше за 5 MiB.

Усе інше відхиляється під час SMTP-сесії, тож сервер відправника дізнається про це й сам формує bounce. Відхилене повідомлення ніколи не зберігається й ніколи не зараховується до вашого споживання.

Прийнята пошта очищується перед збереженням: HTML проходить через санітайзер зі списком дозволеного, а консоль рендерить його в ізольованому фреймі, де віддалені зображення заблоковані, доки ви їх не запросите. Написати на одноразову адресу може будь-хто, тож вміст вважається написаним зловмисником.

Ліміти розміру однакові на всіх планах:

| | Ліміт |
| --- | --- |
| Один лист | 5 MiB. Більший лист відхиляється, а не обрізається. |

## Як завершується адреса {#lifecycle}

| | Що відбувається | Чи можна скасувати? |
| --- | --- | --- |
| **Вимкнення** | Адреса перестає приймати пошту й зберігає те, що вже має; надіслані на неї листи відхиляються. | Так — увімкніть її знову |
| **Видалення** | Адресу та її пошту видалено, а адресу виведено з обігу: вона більше ніколи не видається ні вам, ні комусь іншому. | Ні |
| **Закінчення строку дії** | У момент `expires_at` — те саме, що й видалення. Строк дії спливає лише в безкоштовних адрес (24 години) та адрес, створених з `expires_in_minutes`. | Ні |

Видалення — це `DELETE /v1/inboxes/{id}`; старіші версії цієї документації та журнал аудиту API називають його *release*. Адреса, виведена з обігу, навмисно ніколи не видається повторно: повторно використана адреса доставила б лист для скидання пароля незнайомця тому, хто отримав її наступним. Подробиці, зокрема як повʼязані закінчення строку дії та зберігання, — на сторінці [Адреси та фраза](/docs/product-inboxes/addresses#lifecycle).

## Читання через API {#reading}

Повідомлення можна читати в консолі на будь-якому плані, включно з безкоштовним. Читати їх **програмно** дають змогу платні плани: `GET /v1/inboxes/{id}/messages` повертає розібране повідомлення, обидві частини тіла, вердикти автентифікації та поле `extracted` з одноразовим кодом, якщо ми його знайшли, — а зазвичай тесту потрібен лише він.

Кожен маршрут приймає `id` скриньки. Консоль показує його на картці адреси з кнопкою копіювання. Якщо у вас є лише адреса, знайдіть скриньку за нею:

```bash
curl "{{INBOXES_BASE_URL}}/v1/inboxes?address=ff25m3tue9vm@nninbox.com" \
  -H "Authorization: Bearer $INBOXES_API_KEY"
```

Відповідь — звичайний список щонайбільше з одним елементом. `GET /v1/inboxes` і `GET /v1/inboxes/{id}` повертають `id`, `address` і `phrase` разом, тож один виклик дає все потрібне, щоб надсилати й читати.

## Як отримати доступ {#access}

Зареєструйтеся в Inboxes — і отримаєте робочий простір на безкоштовному плані: одна адреса одночасно, зберігання 24 години й читання в консолі. Ціни наведено на [сторінці Inboxes](/inboxes).

Ключі не видаються разом із робочим простором, і API Inboxes їх не випускає. Випустіть ключ у консолі акаунта NimbusNexus у розділі **API keys**, вибравши продукт **Inboxes**: API-ключі для всієї платформи випускає лише Identity. Ключ — це JWT, тож він починається з `eyJ`. Передавайте його як `Authorization: Bearer <key>` або `X-API-Key: <key>`.

Виберіть область дії під час випуску ключа: `admin` може створювати, змінювати й видаляти адреси, а також читати, `read` може лише читати. Ключ Inboxes не можна обмежити одним проєктом.

> **Ключ `inbx_…` більше не проходить автентифікацію.** Раніше Inboxes випускав власні ключі з цим префіксом. Якщо у вас такий є, випустіть заміну в консолі акаунта.

## Чого продукт не робить {#not}

- **Він не надсилає.** API для надсилання чи ретрансляції немає. Адреса, з якої можна було б надсилати пошту, стала б спам-сервісом.
- **Це не архів.** Повідомлення видаляється, коли спливає строк зберігання плану, а все, що має адреса, зникає, коли адресу видаляють або коли вона спливає.
- **Він поки не пересилає.** Пересилання отриманого на ваш URL заплановано, але ще не реалізовано.
- **Він не перехоплює HTTP.** Скринька лише отримує пошту. Для вебхуків та інших HTTP-запитів використовуйте [Request Bins](/docs/product-bins): його URL-адреси записують будь-який надісланий на них запит.
