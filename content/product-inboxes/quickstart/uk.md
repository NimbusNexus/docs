# Швидкий старт Inboxes

Від нуля до того, що можна перевірити в тесті. Ви створите скриньку, надішлете справжній лист на її адресу і прочитаєте з нього одноразовий код.

## Перш ніж почати {#before}

- **У консолі, на будь-якому плані.** Відкрийте Inboxes, виберіть **Create an inbox**, а потім **Create inbox**: мітка необовʼязкова, а час життя спершу має значення вашого плану за замовчуванням. Сторінка нової скриньки показує, куди саме надсилати: адресу і її фразу, якщо вона є, кожну з кнопкою копіювання. Те, що надходить, зʼявляється в списку нижче за кілька секунд. На безкоштовному плані на цьому все.
- **Через API, на платному плані.** Для програмного читання потрібен Starter або вищий план — на безкоштовному маршрути повідомлень відповідають `not_entitled`. Також вам потрібен API-ключ, випущений у консолі акаунта для продукту **Inboxes**; див. [Як отримати доступ](/docs/product-inboxes#access).

Усі шляхи нижче відносні до `{{INBOXES_BASE_URL}}`, і кожен запит містить `Authorization: Bearer <your key>`.

## 1. Створіть скриньку {#allocate}

```bash
curl -X POST {{INBOXES_BASE_URL}}/v1/inboxes \
  -H "Authorization: Bearer $INBOXES_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"phrase": true}'
```

```json
{
  "id": "inb_7f820a77f64ea18174499945",
  "address": "ff25m3tue9vm@nninbox.com",
  "transport": "email",
  "phrase": "nn-re89dr",
  "status": "enabled",
  "expires_at": null
}
```

Важливі три поля:

- **`address`** — те, що ви даєте системі, яку тестуєте.
- **`phrase`** має бути в темі всього, що надсилають на цю адресу, інакше лист відхиляється: саме це не дає використати адресу, що витекла, для реєстрацій. На платному плані фраза вмикається за бажанням: без `"phrase": true` ви отримуєте `"phrase": ""`, і адреса приймає будь-яку тему.
- **`id`** — те, що приймають усі подальші виклики. Збережіть його.

`expires_at` дорівнює `null`, бо платна адреса існує, доки ви її не видалите; надішліть `expires_in_minutes`, щоб отримати адресу, строк дії якої спливе сам.

`transport` завжди дорівнює `"email"`, бо скринька лише отримує пошту. `POST /v1/inboxes` приймає `"transport": "email"` або запит зовсім без `transport`; будь-яке інше значення, як-от `"http"`, відхиляється з `422` `validation_error`. Щоб записувати HTTP-запити, використовуйте [Request Bins](/docs/product-bins).

## 2. Надішліть на неї лист {#send}

Тут немає нічого специфічного для NimbusNexus — надсилайте з того, що тестуєте. Єдине правило стосується теми:

```text
To:      ff25m3tue9vm@nninbox.com
Subject: nn-re89dr Your verification code
```

Тема без фрази відхиляється під час SMTP-сесії. Ваш відправник про це дізнається, і нічого не зберігається, тож відсутнє тут повідомлення — це справжня відмова, а не тиха втрата.

## 3. Прочитайте його {#read}

```bash
curl "{{INBOXES_BASE_URL}}/v1/inboxes/inb_7f820a77f64ea18174499945/messages?extract=otp" \
  -H "Authorization: Bearer $INBOXES_API_KEY"
```

```json
{
  "items": [
    {
      "id": "msg_bd160c0bcf8db20fba4e535d",
      "from_addr": "noreply@example.test",
      "subject": "nn-re89dr Your verification code",
      "received_at": "2026-08-18T09:12:04Z",
      "extracted": { "otp": "100017" }
    }
  ],
  "next_offset": null,
  "next_until": null
}
```

Уся суть — у `extracted.otp`. Тесту, що перевіряє процес реєстрації, зазвичай потрібне рівно одне — код, — і `?extract=otp` додає його у відповідь списку, тож у типовому випадку другий запит не потрібен. Без `extract` поле `extracted` дорівнює `null`; `extract=links` натомість повертає посилання з повідомлення, а `extract=all` — і те, і те.

Щоб знайти одне повідомлення серед багатьох, шукайте в списку: `q=verification` залишає повідомлення, що містять цей текст, а `in=subject` (або `from`, `headers` чи `body`) звужує, де шукати. Пошук гортає сторінки за `next_until`, а не за `next_offset`; усі параметри описано в розділі [Пошук повідомлень](/docs/product-inboxes#search).

Щоб отримати повне повідомлення, включно з обома частинами тіла, вердиктами SPF/DKIM/DMARC і заголовками:

```bash
curl {{INBOXES_BASE_URL}}/v1/inboxes/inb_7f820a77f64ea18174499945/messages/msg_bd160c0bcf8db20fba4e535d \
  -H "Authorization: Bearer $INBOXES_API_KEY"
```

**Маєте лише адресу?** Знайдіть скриньку, щоб отримати її `id`:

```bash
curl "{{INBOXES_BASE_URL}}/v1/inboxes?address=ff25m3tue9vm@nninbox.com" \
  -H "Authorization: Bearer $INBOXES_API_KEY"
```

## Опитування замість push {#polling}

Немає ні потоку, ні колбеку. Пошта надходить за кілька секунд, тож опитуйте маршрут списку: достатньо короткого інтервалу протягом кількох секунд — саме так робить і сама консоль.

Не опитуйте фіксовану кількість разів, перевіряючи лише останню відповідь. Перевіряйте, що повідомлення *зʼявляється*, з тайм-аутом, інакше повільний відправник виглядатиме як зламаний.

## Прибирання {#cleanup}

Строк дії платної адреси ніколи не спливає, якщо тільки ви не створили її з `expires_in_minutes`, а кожен план обмежує, скільки адрес можна мати одночасно, — тож видаліть адресу, коли закінчите:

```bash
curl -X DELETE {{INBOXES_BASE_URL}}/v1/inboxes/inb_7f820a77f64ea18174499945 \
  -H "Authorization: Bearer $INBOXES_API_KEY"
```

Видалення **остаточне**: скриньку та її вміст видалено, а адресу виведено з обігу, тож її більше ніколи не можна видати ні вам, ні комусь іншому. Це навмисно: повторно використана одноразова адреса доставила б у вашу скриньку чужу пошту. Щоб натомість тимчасово зупинити адресу, змініть її через `PATCH` на `{"status": "disabled"}`, а пізніше увімкніть знову. У консолі обидві дії — у меню ⋯ на сторінці скриньки: **Delete inbox…** і **Disable**.
