# Request Bins

NimbusNexus Request Bins дає вам **bin-и**: публічні URL-адреси, що записують кожен надісланий на них HTTP-запит — з будь-яким методом, на будь-який шлях під URL, з будь-яким тілом. Націльте на bin будь-що, що надсилає HTTP-запити, — провайдера вебхуків, власний застосунок, скрипт, CI-задачу — і прочитайте, що саме надійшло: метод, шлях, query, заголовки, тіло й адресу, з якої прийшов запит, — у консолі або через REST API.

> **Не та сторінка?** Bin записує те, що отримує, і відповідає кожному відправнику однаково. На платному плані він може також передавати кожен запит далі на один ваш URL у тому вигляді, у якому запит надійшов ([Пересилання](/docs/product-bins/forwarding)), але не перевіряє підписів і не доставляє на кілька ендпоінтів. Щоб перевіряти вебхуки провайдера й доставляти їх як події на ваші ендпоінти, з dead-letter чергою та повторною доставкою, використовуйте [джерело Webhooks](/docs/product-webhooks/sources).

## Коротко {#at-a-glance}

| | |
| --- | --- |
| Що ви створюєте | **Bin**: URL на кшталт `https://nnbin.net/b/k7xq2mbn9tfa` |
| Що він записує | Кожен запит на цей URL або на будь-який шлях під ним, з будь-яким методом (`GET`, `POST`, `PROPFIND` з WebDAV, власний метод відправника), будь-якими заголовками й будь-яким тілом |
| Що отримує відправник | `200` і `{"status":"accepted"}`, одразу |
| Пересилання | На Starter, Pro і Custom bin може також надсилати кожен запит далі на ваш власний https-URL ([Пересилання](/docs/product-bins/forwarding)) |
| Консоль | `https://bins.nimbusnexus.net` |
| Базовий URL API | `https://bins.nimbusnexus.net/v1` |
| Автентифікація | `Authorization: Bearer <key>`, ключ, створений у консолі акаунта для продукту **Request Bins** |
| Ідентифікатор, який приймає кожен маршрут | `id` bin-а, напр. `bin_3f9a1c7e5b2d8f4a6c0e9b17`, а не його URL |
| Як знайти bin за URL | `GET /v1/bins?url=<url>` |
| Як прочитати, що надійшло | `GET /v1/bins/{id}/requests` (платні плани; на Free — у консолі) |
| Усі маршрути, що відповідає URL bin-а, ролі й ліміти | [Довідник Request Bins](/docs/product-bins/reference) |

## Як це працює {#how}

1. **Створіть** bin — у консолі кнопкою **New bin** або через `POST /v1/bins`. Його URL записує запити з цієї миті.
2. **Надішліть** на нього запити. Дайте URL тому, за чим хочете спостерігати, — вставте його в налаштування вебхуків провайдера, у конфігурацію застосунку, у скрипт, у CI-задачу — або викличте його самі через `curl`. Усе, що йде після slug-а, обираєте ви: запит на `https://nnbin.net/b/k7xq2mbn9tfa/orders/42` записується зі шляхом `/orders/42`.
3. **Прочитайте**, що надійшло. Запит зʼявляється в консолі за кілька секунд, а на платних планах — і в `GET /v1/bins/{id}/requests`. Щоб знайти один запит серед багатьох, шукайте текст у шляхах, заголовках і тілах або залиште лише деякі методи: у консолі — **Search** і чипи методів над списком, в API — `q` і `method` ([Перехоплені запити](/docs/product-bins/reference#requests)). Щоб побачити, які шляхи використовував відправник, перемкніть список на **By path**: він рахує запити на кожен шлях, а якщо вибрати один зі шляхів, показує список його запитів. В API те саме робить `GET /v1/bins/{id}/paths` ([Запити за шляхами](/docs/product-bins/reference#paths)).
4. **Видаліть** bin, коли закінчите, або дайте йому спливти.

Усі чотири кроки показано на сторінці [Швидкий старт](/docs/product-bins/quickstart).

Використовуйте `url` саме в тому вигляді, у якому його повертає API. URL-адреси bin-ів розміщені на власному домені, `nnbin.net`, а не на `{{ROOT_DOMAIN}}`.

## Що отримує відправник {#answers}

Bin одразу відповідає на кожен запит `200` з тілом `{"status":"accepted"}` — незалежно від того, записав він запит чи ні. Так само відповідає вимкнений чи призупинений bin або bin, що вичерпав місячний обсяг запитів свого плану, а також URL, чий bin ніколи не існував або був видалений. Це навмисно: відправник, який отримує помилку, може припинити надсилання або вимкнути ваш вебхук, а інша відповідь для живого bin-а дала б будь-кому змогу перебором шукати bin-и.

Будь-що інше URL bin-а відповідає, лише коли нічого не записано:

- `429` з `Retry-After`, коли відправник або bin перевищує свій поминутний ліміт;
- `503` з `Retry-After`, коли запит саме зараз не вдалося зберегти, тож відправнику слід надіслати його знову;
- `404`, коли slug в URL — не такий, який Request Bins міг би колись видати.

Подробиці — у довіднику: [Що відповідає URL bin-а](/docs/product-bins/reference#edge-answers).

## Що записується {#recorded}

Для кожного запиту bin зберігає метод, шлях після slug-а, рядок query, заголовки в порядку надходження, тіло, адресу, з якої прийшов запит, і час надходження. Що саме ви прочитаєте, визначають кілька правил:

- **Тіла зберігаються повністю, до 1 MiB.** Від більшого тіла лишається перший 1 MiB, `truncated` дорівнює `true`, а `size_bytes` усе одно показує, яким великим воно було насправді.
- **Облікові дані приховуються.** Значення `Authorization`, `Proxy-Authorization`, `Cookie`, `Set-Cookie` і `X-API-Key` замінюються на `[redacted]` ще до того, як щось буде збережено. Усі інші заголовки зберігаються такими, як їх надіслали, включно із заголовками підпису, бо саме підпис вам треба бачити, коли його перевірка не проходить.
- **Нічого не змінюється й не виконується.** Тіло зберігається тими байтами, що надійшли, а консоль показує його як текст, ніколи як розмітку.
- **Кожен запит — окремий рядок.** Запит, надісланий знову з тими самими методом, шляхом, рядком query й тілом, зберігається ще раз, з власними заголовками, адресою й часом, тож кожну повторну спробу відправника можна відкрити окремо.

## Пересилання {#forwarding}

На Starter, Pro і Custom bin може також надсилати кожен записаний запит далі на ваш власний сервер. Задайте йому URL пересилання — і метод, шлях, query, заголовки й тіло підуть на цей URL такими, якими надійшли, а відправник, як і раніше, одразу отримає `200` від bin-а. Якщо ваш сервер дає збій, bin пробує знову, а відповідь вашого сервера зберігає поруч із запитом, тож ви бачите, що надіслав відправник і що з цим зробив ваш ендпоінт. Облікові дані не пересилаються: заголовки, які bin приховує, ніколи не виходять за його межі. Правила, повтори, ліміти й адресу, з якої надходять пересилання, описано на сторінці [Пересилання](/docs/product-bins/forwarding).

| Читання через API | ні (лише консоль) | так | так | так |

| Надсилань форм із браузера на bin | 3 | 5 | 5 | 10 |

Free достатньо, щоб побачити, що саме надсилає будь-який застосунок, скрипт чи сервіс: один bin, 1 000 запитів на місяць, читання в консолі.

Місяць — це календарний місяць за UTC, і зараховується кожен запит, який записує bin. Після вичерпання місячного обсягу запитів bin-и й далі відповідають `200` і нічого не записують до початку наступного місяця; запити, відхилені в такий спосіб, не зараховуються. Один bin може використати лише частину місячного обсягу — увесь обсяг на Free, половину на Starter, 40 % на Pro і чверть на Custom, — тож один завантажений URL або URL, що потрапив у чужі руки, не вичерпає запитів інших bin-ів робочого простору.

Останні два рядки — це ліміти проти зловживань, описані в розділі [Призупинені bin-и](#suspended).

## Призупинені bin-и {#suspended}

URL bin-а публічний: надсилати на нього може кожен, у кого він є. Через це bin був би зручним місцем, щоб збирати те, що відправляє форма фішингової сторінки, або дані, викрадені з чужих машин, тож bin призупиняється, коли його трафік схожий на таке:

- він отримує запити з більшої кількості різних адрес, ніж дозволяє ліміт плану **різних відправників**; або
- він отримує з браузерів більше надсилань форм, ніж дозволяє ліміт плану **надсилань форм із браузера**, щонайменше з трьох адрес.

Призупинений bin і далі відповідає `200` і нічого не записує. Причину показує консоль, а в API — `suspended_code`. Призупинення встановлюємо ми, це не ваш перемикач: увімкнення bin-а його не знімає, тож якщо вважаєте призупинення помилковим, зверніться до підтримки. Bin-и також тимчасово блокуються, але не видаляються, коли після зміни плану в робочому просторі лишається більше bin-ів, ніж дозволяє новий план, а також поки робочий простір призупинено через неоплачений платіж; кожен повертається, щойно його причину усунуто.

Щоб повідомити про URL bin-а, яким зловживають, напишіть на `abuse@nnbin.net` і вкажіть повний URL.

## Як отримати доступ {#access}

Відкрийте консоль за адресою `https://bins.nimbusnexus.net` і увійдіть зі своїм акаунтом NimbusNexus або додайте Request Bins через **Add a product** у будь-якій консолі NimbusNexus. Перший візит власника чи адміністратора робочого простору додає Request Bins до робочого простору; відтоді його можуть відкривати й інші учасники. Особистий робочий простір починає з Free, а командний — із 7-денного пробного періоду Starter.

API Request Bins не випускає ключів. Створіть ключ у [консолі акаунта]({{ACCOUNT_BASE_URL}}/api-keys?product=bins) у розділі **API keys**, вибравши продукт **Request Bins**. Ключ — це JWT, тож він починається з `eyJ`. Передавайте його як `Authorization: Bearer <key>` або `X-API-Key: <key>`.

Виберіть дозвіл ключа під час створення: **Read** читає bin-и й те, що вони записали, а **Read & write** також може створювати, змінювати, очищати й видаляти bin-и. На Free ключ може керувати bin-ами, але для читання записаного через API потрібен Starter або вищий план; консоль читає записане на будь-якому плані. Повна таблиця, включно з ролями робочого простору, — у розділі [Хто що може робити](/docs/product-bins/reference#authority).

## Чого продукт не робить {#not}

- **Він не відповідає так, як задасте ви.** Кожен bin відповідає `200` з `{"status":"accepted"}`; статус, заголовки чи тіло на ваш вибір не реалізовано.
- **Він не переграє запити.** Записаний запит не можна надіслати знову на вимогу. [Пересилання](/docs/product-bins/forwarding) надсилає кожен запит далі один раз, щойно той надходить.
- **Він не працює в режимі push.** Немає ні потоку, ні колбеку: опитуйте `GET /v1/bins/{id}/requests` із `since`, як це робить консоль кожні 3 секунди.
- **Це не архів.** Запит видаляється, коли спливає строк зберігання плану, а все, що є в bin-і, зникає, коли bin видаляють або коли він спливає.
- **Він не розділяє робочий простір за проєктами.** Request Bins обслуговує робочі простори цілком, тож гостьові місця й ключі, обмежені одним проєктом, отримують відмову.
